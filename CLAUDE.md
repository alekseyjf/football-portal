# Football Portal — Project Context

## Stack
- **Web** (port 3000): Next.js 16, React 19, Tailwind 4, React Hook Form + Zod, Zustand, Vitest (unit), **TanStack Query** (`prefetchQuery` + `HydrationBoundary` для головної, новини й матчу; хуки для коментарів і auth), **next-intl** (маршрути `app/[locale]/…`, локалі лише `en` | `uk` — той самий код у БД, API і `<html lang>`, D22)
- **Admin** (port 3001): Next.js 16, React Hook Form + Zod, Zustand, **TanStack Query** (пости, логін, створення поста)
- **API** (port 4000): NestJS, Prisma 7, PostgreSQL (Supabase), JWT httpOnly cookies
- **Monorepo**: pnpm + Turborepo; нову версію пакета pnpm бере не раніше ніж через 7 днів після публікації (`minimumReleaseAge` у `pnpm-workspace.yaml`)
- `packages/types` — типи API для web і admin, **згенеровані** з OpenAPI (D28): `pnpm gen:api-types` (без сервера й БД; і `pnpm install`) → `openapi.json` + `src/generated/openapi.ts` — **не в git**; імена (схема без `Dto`) — по файлу на сутність у теці модуля API (`src/football/match.ts`)
- `packages/validation` — спільні межі валідації: `.` — числа (API DTO на class-validator) і slug (`slugify`, `slugifyTitle`, `slugifyTagName`, `SLUG_PATTERN` — одна транслітерація для API і підказки адмінки, D24), адреси сторінок сайту (`publicTagPath` — `/{locale}/news/tag/{slug}`, D51), формат коду турніру й slug-а клубу (`COMPETITION_SLUG_PATTERN`, `CLUB_SLUG_MAX_LENGTH` — фільтри стрічки в API і web, D52), посилання YouTube (`parseYouTubeVideoId`, `normalizeYouTubeUrl` — API, адмінка й сайт, D54), `./forms` — zod-схеми форм web/admin (і тегу — `tagFormSchema`). Збирається в `dist` (turbo `dev`/`build` — першим; `pnpm install` — через `prepare`); тести — Vitest
- `packages/ui` — спільний UI web і admin: `MarkdownContent` (текст новини, D25) — **без збірки** (D49): `exports` на `src`, у застосунках — `transpilePackages` і `@source` у `globals.css`; вигляд тексту — `@tailwindcss/typography` (`@plugin` там же); свої lint, typecheck, Vitest. Кеш Turbopack, старший за `@source` (`apps/*/.next/dev`), класів пакета не бачить — видалити раз
- `packages/config` — shared tsconfig (ESLint — свій `eslint.config.mjs` у кожному застосунку; web і admin — однаковий `eslint-config-next`)

## Auth
- Access JWT 15 хв (HS256, `{ sub, role, sid }`, `sid` = `AuthSession.familyId`) + opaque refresh (у БД — SHA-256), **httpOnly cookies**; refresh — ротація, ковзне вікно 7 д, **абсолютний ліміт 30 д** від логіну
- `JwtStrategy` на кожен запит перевіряє, що сесія `sid` жива → logout / logout-all / блокування гасять access одразу
- Roles: `ADMIN`, `USER`; доступ до роуту — `@AuthRequired()` / `@AdminOnly()` / `@AuthOptional()` (`auth/guards/access.decorators.ts`: guard-и + опис у Swagger); користувач у контролері — `@CurrentUser()` / `@OptionalCurrentUser()`, не `req.user`
- Адмінка логіниться через `POST /auth/login/admin` (не-ADMIN → 403 `ADMIN_ONLY`, сесія не створюється); cookies спільні на localhost
- Пароль: новий ≥ 8 і ≤ 72 **байти** UTF-8 (межа bcrypt; `PASSWORD_MAX_BYTES`, API — `@MaxUtf8Bytes`, межі — `packages/validation`); логін — без мінімуму (старі акаунти)

## Database (Prisma schema v5)
Джерело правди — `apps/api/prisma/schema.prisma` + `prisma/sql/constraints.sql` (CHECK і partial unique, яких Prisma не виражає: одна ціль треду, різні клуби матчу, дата в опублікованого поста, одна default-мова, один `isCurrent` сезон, один `RUNNING` синк, формат анонімізованого email, формат slug-а й назва тегу, одна закріплена новина, коментар — лише один рівень + частковий індекс коренів). Рішення D1–D20 — `docs/decisions/v5-foundation.md` (усі рішення — `docs/decisions/`). Міграції — `0001_init` … `0012`; squash — перед першим прод-деплоєм (M3.1). **Дати — лише `DateTime @db.Timestamptz(3)`** (з 0010 — усі, backend Rule 18); `migrate deploy` міграцію в транзакцію не загортає — до міграції на багато таблиць — ідемпотентний SQL відкату; відкат успішної міграції — `rolled_back_at` у `_prisma_migrations`, не `resolve --rolled-back` (лише для невдалої) — v5-foundation, розділ 11.
- **Identity:** `User` — лише ідентичність: email (always lowercase), `passwordHash` (bcrypt), `role`, `status` (ACTIVE | LOCKED | DELETED), `lockedAt`, `deletedAt`; `UserProfile` 1:1 — `displayName`, `avatarUrl`, `bio`; `AuthSession` — refresh-сесії (`familyId`, `tokenHash`, `expiresAt`, `revokedAt`)
- **Moderation:** `UserSanction` (історія санкцій), `RateLimitEvent` (cooldown / burst), `BlockedEmail` (HMAC пошти видаленого акаунта)
- **Content:** `Language` (`isDefault` = en) · `Post` — `number` (унікальний, послідовність; URL `{slug}-{number}`, D24), slug (з EN-заголовка, не унікальний), `status` (DRAFT | SCHEDULED | PUBLISHED | ARCHIVED), `publishedAt`, `coverImageUrl`, `coverImageCredit` (підпис автора фото, D44), videoUrl, `sourceUrl` + `sourceName` (джерело — одне на пост, D26), authorId, `likeCount` / `dislikeCount`, `pinnedAt` + `pinnedById` (головна новина сайту, D56), deletedAt (soft delete) · `PostTranslation` — `(postId, languageCode)`, title, excerpt (простий текст), content (**Markdown**, D25: API не парсить — лише довжина; рендер — `packages/ui`), `coverImageAlt` (опис фото мовою перекладу, D44) · `Tag` / `TagTranslation` / `PostTag` · `PostCompetition`, `PostClub` (новини турніру / клубу)
- **Engagement:** `CommentThread` — рівно одна ціль (`postId?` | `matchId?`, CHECK), `isLocked`, `commentCount` · `Comment` — threadId, authorId, parentId? = rootId? (один рівень, D27), depth 0 / 1, `replyToCommentId?` / `replyToUserId?` (адресат відповіді на відповідь), content, replyCount, likeCount, pinnedAt, editedAt, deletedAt · `PostLike` / `CommentLike` / `MatchLike` — YouTube-style (LIKE/DISLIKE, only LIKE shown publicly) · `UserReactionActivity` (журнал реакцій)
- **Football:** `Area` · `Competition` (`type` LEAGUE|CUP, `isActive`, `sortOrder`) · `Season` (`label` «2025/26» / «2026», рівно один `isCurrent`) · `SeasonClub` (M:N клуб ↔ сезон) · `Club` (`kind` CLUB|NATIONAL, `slug` не змінюється) · `Match` (`kickoffAt`, `stage`, `groupName`, half-time, пенальті, `winner`) · `Standing` (`stage`, `groupName` `''` = без групи, `type`)
- **Sync:** id провайдера — лише в `*ExternalRef` (`payloadHash`), журнал / лок — `SyncRun`. FOOTBALL-таблиці про провайдерів не знають

## API Structure (NestJS)
All routes prefixed with `/api/v1/`. Swagger UI — `/api/docs` (JSON — `/api/docs-json`), на проді вимкнений. Контракт (D28, backend Rule 11): response DTO — `dto/<сутність>-response.dto.ts`, метод контролера повертає `Promise<XDto>` (схему бере CLI-плагін), помилки — `@throws {404} CODE` у JSDoc; спільне (помилка `default`, 400 валідації) — `src/openapi/openapi-document.ts`

### Posts — `src/posts/`
- **Живий пост** (`post-visibility.ts`, `livePostWhere`): `deletedAt IS NULL`, `status IN (PUBLISHED, SCHEDULED)`, `publishedAt <= now` — SCHEDULED виходить сам, без cron. Чернетки за slug → 404, лайк чернетки — 404. Стрічка й новина за номером — `publicPostWhere` (+ переклад default-мови; ним же фільтрує публічний список тегів)
- `GET /posts?page=1&limit=10&lang=en&tags=&competition=&club=` — public, живі, `publishedAt desc`; `limit` ≤ 50. Фільтри (D46, `post-feed-filter.ts`): slug-и через кому, ≤ 20 (`IsSlugList`); усередині фільтра — АБО, між — І; турнір — лише явна прив'язка `PostCompetition`; невідомий slug → порожньо (200), не той формат / повтор параметра → 400. Переклад розгорнуто в пост (`title`, `excerpt`, `coverImageAlt`) з fallback на default-мову + `resolvedLanguage`; невідомий `lang` → default. У новині — `tags` і `competitions` (у порядку редакції): з них сайт будує рубрику картки (D52)
- `GET /posts/home?lang=` — public, головна сайту `{ lead, latest }` (D56): головна — закріплена, інакше найсвіжіша; `latest` — 6 найсвіжіших без неї (`pickHomePosts`, `post-pin.ts`). Маршрут — раніше за `:number`
- **Головна новина** (D56, `post-pin.ts` — правила, `PostPinService`): `POST /posts/:id/pin` `{ replacesPostId: string | null }` (обов'язкове) і `DELETE /posts/:id/pin` — ADMIN → 200 `AdminPostDto`; лише жива (інакше 409 `POST_NOT_LIVE`), закріплена не `replacesPostId` (і паралельне закріплення — частковий унікальний індекс `Post_single_pinned_idx`) → 409 `PINNED_POST_CHANGED`; заміна — одна транзакція (`FOR NO KEY UPDATE`: нова → закріплена); `PUT`, що робить новину неживою, і `DELETE /posts/:id` знімають закріплення тим самим записом; записи — сирим SQL (`updatedAt` — дата збереження тексту, не зсувається). `pinnedAt` / `pinnedBy` — **лише** у відповідях `/posts/admin/…` і записів, публічні — без них; `GET /posts/admin/pinned` → `{ post: AdminPostDto | null }` (раніше за `admin/:id`)
- `GET /posts/admin/all?page=&limit=&status=&search=` — ADMIN, сторінка `{ data, total, page, limit, totalPages }` (`limit` 20, ≤ 100; нові першими), усі крім видалених: рядок — `status`, `publishedAt`, `isLive`, `pinnedAt`, `pinnedBy`, `translations: [{ languageCode, title }]`. Правило — `admin-post-filter.ts` (D47): `status` — як бачить редактор (запланована, чия дата настала, — серед PUBLISHED), `search` — підрядок заголовка будь-якою мовою без регістру; `%` / `_` — як текст (`prisma/prisma-text-search.ts`: Prisma 7 `contains` їх не екранує)
- `GET /posts/admin/:id` — ADMIN, новина для форми (будь-який статус; видалена → 404 `POST_NOT_FOUND`): переклади з текстом, медіа, джерело; теги / турніри / клуби — чипи `AdminTagRefDto` / `CompetitionRefDto` / `ClubRefDto` (один формат з вибором у формі, D47; select-и — `ADMIN_TAG_REF_SELECT` (`tag.repository.ts`), `COMPETITION_REF_SELECT` і `CLUB_REF_SELECT` (`football/football-refs.ts`)). Маршрут `admin/all` оголошено раніше за `admin/:id`
- `GET /posts/:number?lang=en` — public, живий пост **за номером** (ціле 1…2³¹−1, інакше 400) + `content`, `coverImageCredit`, `sourceUrl`, `sourceName`, `availableLanguages`, `tags`, `competitions`, `clubs` (коментарі — окремо, `GET /comments/post/:postId`); `slug` у відповіді — канонічний (web робить 308)
- **Slug** (`post-slug.ts`, D24; транслітерація — `slugify` / `slugifyTitle` з `packages/validation`, спільні з тегами й підказкою адмінки): один на всі мови, з EN-заголовка; поки `publishedAt` порожній — іде за EN-заголовком, щойно дата є — лише явний `slug` у `POST` / `PUT` (`resolveUpdatedPostSlug`)
- `POST /posts` — **ADMIN only**, body: `{ translations: [{ languageCode, title, excerpt, content, coverImageAlt? }], slug?, status?, publishedAt?, coverImageUrl?, coverImageCredit?, videoUrl?, sourceUrl?, sourceName?, tagIds?, clubIds?, competitionIds? }`; переклад default-мови (`Language.isDefault`, en) обов'язковий, решта — опційні (D23; `findTranslationLanguagesError` — спільне з тегами, `languages/translation-languages.ts`); без `status` — DRAFT. Правила статусу / дати — `post-publication.ts` (`resolvePostPublication`)
- **Обкладинка** (`post-cover-image.ts`, `resolvePostCoverImage`, D44): PUBLISHED / SCHEDULED з обкладинкою — опис у кожному перекладі й підпис (інакше 400 `COVER_IMAGE_ALT_REQUIRED` / `COVER_IMAGE_CREDIT_REQUIRED`), чернетка — будь-яка; інша адреса фото чи без фото — наявні опис і підпис не лишаються (`coverImageTextToStore`), переклад вимкненою мовою опису не потребує
- **Відео** (D54): лише YouTube (`watch?v=`, `youtu.be/`, `/shorts/`, `/embed/`; https) — `@IsYouTubeVideoUrl()` (`common/validation/url-field.decorators.ts`) нормалізує до валідаторів, у БД і відповідях — канонічне `https://www.youtube.com/watch?v={id}`; інше → 400, `null` — прибрати
- **Джерело** (`post-source.ts`, `resolvePostSource`, D26): назва без адреси → 400 `SOURCE_URL_REQUIRED`; назва — про конкретну адресу (як опис фото, D44): інша адреса старої назви не успадковує, `sourceUrl: null` прибирає джерело цілком; «передане або наявне» для правил — `requestedOrCurrent` (`post-field-update.ts`)
- `PUT /posts/:id` — **ADMIN only**; переклади — upsert за мовою, масив зв'язків замінює повністю
- `DELETE /posts/:id` — ADMIN only, soft delete (sets deletedAt) → `{ id }`
- Files: `post.controller.ts`, сервіси за use case (D47) — `public-post.service.ts` (стрічка, новина за номером), `admin-post.service.ts` (список і новина для адмінки), `post-editor.service.ts` (створення, зміна, видалення), `post-pin.service.ts` (головна новина); репозиторії — `public-post.repository.ts`, `admin-post.repository.ts` (читання адміном і записи), `post-pin.repository.ts`; `post.module.ts`, `post-response.ts` (форма відповідей), `admin-post-filter.ts`, `post-publication.ts`, `post-slug.ts`, `post-cover-image.ts`, `post-source.ts`, `post-field-update.ts`, `post-visibility.ts`, `post-feed-filter.ts`
- DTOs: `post-fields.dto.ts` (спільні поля + `PostTranslationDto`), `create-post.dto.ts`, `update-post.dto.ts`, `list-posts-query.dto.ts`, `list-admin-posts-query.dto.ts`, `post-number-param.dto.ts`, `admin-post-response.dto.ts`

### Tags — `src/tags/` (D45; сторінка в адмінці — D51)
- `GET /tags?lang=` — public: лише теги з новинами стрічки (`publicPostWhere`), за абеткою назви мовою запиту (`Intl.Collator`); `GET /tags/:slug?lang=` — public, будь-який тег (сторінка тегу), `TAG_NOT_FOUND`. Назва — мова запиту → EN → slug (`toPublicTag`; той самий `TagDto` — у тегах новини)

### Comments — `src/comments/` (один рівень, як на YouTube — D27)
- **Тред** (`CommentThread`) — один на пост / матч, створюється з першим коментарем (не на `GET`); `commentCount` = живі коментарі (заглушка не рахується), `Comment.replyCount` кореня = живі відповіді гілки
- **Гілка** — корінь + відповіді: у відповіді завжди `parentId = rootId`, `depth = 1` (CHECK `Comment_single_level_check`, міграція 0012). Відповідь на відповідь (і від старого клієнта) API пише в корінь гілки з адресатом `replyToCommentId` / `replyToUserId` (обидва `ON DELETE SET NULL`); у відповіді API — `replyTo { commentId, author }`
- `GET /comments?postId=|matchId=&sort=newest&cursor=&limit=` — public (`@AuthOptional`), корені нові першими (`createdAt ↓, id ↓`), 20 / ≤ 50; `GET /comments/:id/replies?cursor=&limit=` — живі відповіді від старих до нових, 10 / ≤ 50. Відповідь `{ items, nextCursor }` (у порції коренів — ще `commentCount` треду: живі корені й відповіді, заглушка — ні), у коментарі — `likeCount`, `myReaction` (одним запитом на порцію; гість — `null`), `replyCount`, `replyTo`, `editedAt`, `isDeleted`. Курсор — keyset, непрозорий base64url `{ v: 1, sort, scope, createdAt, id }` (`comment-cursor.ts`): не той, з іншого списку чи порядку → 400 `COMMENT_CURSOR_INVALID`. `sort` обов'язковий, поки лише `newest` («Популярні» — M2.14). Пост — `publicPostWhere`, інакше 404 `POST_NOT_FOUND`; корінь не в списку → 404 `COMMENT_NOT_FOUND`
- `POST /comments` — authenticated, body: `{ content, postId? | matchId?, parentId? }` → `CommentItemDto`; рівно одна ціль (`COMMENT_TARGET_INVALID`); батько — живий і в тому ж треді (`PARENT_COMMENT_NOT_FOUND` / `PARENT_COMMENT_MISMATCH`), гілка відкрита (корінь живий або заглушка); `isLocked` → 403 `COMMENT_THREAD_LOCKED` (ADMIN — можна)
- `DELETE /comments/:id` — author or ADMIN, soft delete → `{ id }`: відповідь — зникає; корінь з живими відповідями — **заглушка** (похідний стан: `deletedAt` + `replyCount > 0`, `listedRootWhere`; текст і автор — `null`), без відповідей — зникає
- `DELETE /comments/:id/purge` — **ADMIN**, ⚠️ фізичне видалення, лише без жодної відповіді (інакше 409 `COMMENT_HAS_REPLIES`); `…/purge-thread` — **ADMIN**, ⚠️ корінь + усі відповіді гілки (відповідь — лише вона) → `{ id, purgedCount }`
- Гонки: блокування завжди **корінь → ціль → тред**, `FOR NO KEY UPDATE` (не `FOR UPDATE` — той конфліктує з FK-`KEY SHARE` вставки відповіді → deadlock); вставка відповіді спершу оновлює корінь, тож під блокуванням кореня гілка не росте; deadlock / FK-гонка → 409 `COMMENT_THREAD_CHANGED`. Помилки Prisma — лише через `src/prisma/prisma-errors.ts`: Prisma 7 кидає deadlock як `P2010` або «голий» `DriverAdapterError`, **не** `P2034`

### apps/api/.env — схема `src/config/env.schema.ts` (zod, M1.3.2)
- Перевіряється при старті (`config/env.config.ts`: `registerAs` + `ConfigModule.forRoot({ ignoreEnvFile, load })`): немає обов'язкової або значення невалідне → API не стартує й перелічує всі проблеми (без значень); `KEY=` без значення = змінної немає
- У коді — лише `@Inject(envConfig.KEY) env: AppEnv`; `process.env` у `src/` поза `config/env.config.ts` забороняє ESLint (Rule 13). `.env` завантажує `main.ts` (dotenv), а не `ConfigModule` — e2e не підхопить dev-БД випадково
- Обов'язкові: `NODE_ENV` (development | production | test), `DATABASE_URL` (транзакційний пулер :6543), `JWT_SECRET` і `EMAIL_HASH_SECRET` (≥ 32 символи, різні; HMAC — НЕ змінювати після запуску), `CORS_ORIGINS` (рівно origin-и через кому; на проді лише https); на проді ще `TRUST_PROXY` (кількість проксі, напр. 1, або 0 / false; `true` заборонено)
- Опційні (дефолт): `PORT` (4000), `FOOTBALL_API_KEY` (без нього синк → 503), `FOOTBALL_API_URL` (football-data v4, лише https), `FOOTBALL_LIVE_CRON_ENABLED` (false), `FOOTBALL_HTTP_LOG` (true лише в development; явне значення перемагає), `COMMENT_COOLDOWN_MS` (60000, ≤ 24 год — retention `RateLimitEvent`)
- Лише CLI (у схемі немає): `DIRECT_URL` (session-пулер / пряме з'єднання :5432 — `prisma migrate`, seed; порожньо → `DATABASE_URL`), `SEED_ADMIN_EMAIL` / `SEED_ADMIN_PASSWORD` / `SEED_ADMIN_NAME` (`pnpm db:seed` без `seed-data/content.json`). Турніри для синку — з `Competition.isActive`, не з env

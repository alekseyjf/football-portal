# Бэклог: технічний борг і відкладене

> Задачі, які **не** входять у поточну віху, але відомі. Для кожної — чому відкладено і ⏰ тригер (коли повертаємось). Коли задача стає актуальною — переносимо в етап плану.

## Архітектура й код

| Задача | Чому відкладено | ⏰ Тригер |
|---|---|---|
| Спільний пакет для `lib/api/http.ts` (зараз дві копії — web і admin, «міняти разом») | Дві копії поки дешевші за пакет | Перед CSRF-заголовком (OQ-6) або третім клієнтом |
| ⭐ `apiGet` / `apiPost`, типізовані шляхом (`paths` з `generated/openapi.ts`): тип відповіді виводиться з документа, а не пишеться вручну в `apiGet<PostDetail>(…)` — зараз помилку «не той тип для цього URL» компілятор не бачить | Типи вже згенеровані (M1.3.5); шляхи з параметрами (`/posts/${slug}?lang=`) потребують обгортки | Разом зі спільним пакетом `http.ts` або коли клієнтів стане більше |
| ⭐ Оптимістичне блокування при редагуванні поста (`updatedAt` в умові запису → 409 «пост змінив хтось інший») | Редактор поки один | Коли з'явиться другий редактор |
| ⭐ `410 Gone` для навмисно видалених новин (швидше випадають з індексу) | Не критично до проду | M3.7 |
| `GET /comments/post/:id` не перевіряє переклад default-мови (на відміну від деталі поста, P3-5) | Розбіжність лише при порушенні інваріанта | Під час M1.7 |
| `SyncScope.STANDINGS` у enum ніде не використовується | 👤 Лишаємо як резерв | — |
| `packages/ui` — порожня папка | 👤 Лишаємо: туди йде спільний UI (Markdown-рендерер — M1.5 / M1.6) | M1.5 |
| `UserReactionActivity` росте без обмежень | Ще мало даних | M4 (журнал активності, 👤 8.8) — визначити строк зберігання |
| Повний і LIVE-синк одного турніру можуть іти одночасно — повний може на секунди перезаписати свіжіший LIVE-рахунок | Самовиправляється наступним синком | Якщо побачимо на проді |
| SSR невідомої ліги (`?league=NOPE`) — «Завантаження…» до гідрації | Разом зі сторінками ліг | M2.2 |
| ⭐ Перевірка `NEXT_PUBLIC_*` у web / admin під час збірки (як схема env в API): зараз без змінної — дефолт localhost, тож збірка без `NEXT_PUBLIC_API_URL` мовчки ходить на `localhost:4000` | Змінних п'ять, усі з робочими dev-дефолтами (M1.3.2) | M1.11 — перша збірка з тест-URL API |

## Безпека

| Задача | Чому відкладено | ⏰ Тригер |
|---|---|---|
| Cooldown коментарів не атомарний: N паралельних коментарів проходять перевірку разом (до 4) | Далі спрацьовує burst-санкція | Якщо спам пройде — `assert` + `record` під одним advisory-локом |
| ⭐ Прогресивні бани (1 хв → 10 хв → 1 год → 1 день → назавжди) замість «2 strike-и → назавжди» | Спершу вікно 30 днів ([D37](decisions/D37-anti-abuse-strike-window.md)) | M3.2 |
| Чи можна блокувати ADMIN (ручне блокування) | Немає адмінки користувачів | M2.6 |
| Розблокування пошти видаленого акаунта (`BlockedEmail`) з адмінки | Немає адмінки користувачів | M2.6 |
| Enumeration на реєстрації (409 видає зайняту адресу) | Закривається лише підтвердженням пошти | M3.3 |
| `cookies.txt` (тестовий v4-JWT) лишився в публічній історії git | Тестовий адмін, рішення — не чистити історію | На проді — новий `JWT_SECRET` (✅ уже вимога) |
| ⭐ `trustPolicy: no-downgrade` у `pnpm-workspace.yaml` (pnpm ≥ 10.21): встановлення падає, якщо нова версія пакета має слабший рівень довіри, ніж попередні (була provenance / trusted publisher — зникла: типовий слід викраденого токена) | Може зупиняти легальні оновлення без provenance — потрібен `trustPolicyExclude`; спершу `minimumReleaseAge` (M1.3.2) | M3.2 — аудит залежностей |

## Масштабування ([D41](decisions/D41-single-instance-scaling.md))

| Задача | ⏰ Тригер |
|---|---|
| Throttler на Redis (ліміти спільні для інстансів і переживають рестарт) | > 1 інстансу API |
| Анти-абуз на Redis: ковзне вікно порушень (ZSET) замість підрахунку санкцій у БД | > 1 інстансу або навантаження |
| Сховище сесій `sid` у Redis (без запиту до БД на кожен запит) | Навантаження на `JwtStrategy` |
| Окремий worker синку (`NestFactory.createApplicationContext`) + прапорець cron в API | > 1 інстансу API |
| Спільна квота football-data (БД або Redis) | Синк і API — різні процеси |
| Кеш у Redis | > 1 інстансу і виміряна потреба ([D35](decisions/D35-caching-measure-first.md)) |

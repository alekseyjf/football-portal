## 1. Мета і рамки

- 👤 **12Yards.com** — футбольний портал для США і світу: матчі, таблиці, турніри, клуби — і новини, свої та чужі, з обов'язковим посиланням на джерело.
- 👤 Справжній продукт з аудиторією → усе як у справжньому проєкті: пошта, юридичні сторінки, моніторинг, бекапи.
- 👤 Мови: `en` (за замовчуванням) і `uk`; закладено розширення (іспанська тощо).
- 👤 У майбутньому, поза поточними віхами: реклама, інтеграції (молодіжна ліга США від партнера) — `ideas.md`.
- 👤 Команда: власник + AI, 2–4 год на день; темп — «коли буде готово».
- 👤 До проду — лише безкоштовні рівні сервісів; платні вирішуємо в M3 (OQ-22).

### M1.7 Коментарі як на YouTube

**Мета:** ⚠️ зараз дерево до 15 рівнів — має бути як на YouTube ([D27](decisions/D27-youtube-style-comments.md)). 👤 Робимо до тестового деплою.

- [ ] ❓ Перед стартом — модель і сортування (OQ-3).
- [ ] 👤 Один рівень: корінь + відповіді під ним; відповідь на відповідь — у тому ж списку з «@Ім'я» на початку.
  - ⭐ Модель: усі відповіді гілки — `parentId = rootId`; кому відповіли — нове поле `replyToUserId`; наявні дані «сплющуємо» разовою міграцією — *чому:* згадка прив'язана до людини (як на YouTube), тож видалення чи purge однієї відповіді не ламає інші й зовнішні ключі.
- [ ] 👤 Видалили відповідь, на яку відповідали через @згадку, — інші відповіді лишаються (👤 У14).
  - ⭐ Видалення кореня ховає всю гілку — так поводиться YouTube.
- [ ] 👤 Порціями, як на YouTube: корені — «Показати ще»; відповіді згорнуті («▼ N відповідей») і вантажаться порціями.
  - ⭐ Сортування «Популярні» (за замовчуванням, як на YouTube) / «Нові» — *чому:* корисні коментарі не тонуть у потоці.
- [ ] ⭐ Лайки коментарів пачкою: `likeCount` + `myReaction` разом із порцією коментарів — *чому:* ⚠️ зараз N+1 (100 коментарів = 100 HTTP-запитів).
- [ ] ⭐ Редагування свого коментаря протягом 15 хв з позначкою «змінено» (👤 7.4; `editedAt` у схемі вже є) — *чому:* дешево зараз, коли API й компонент усе одно переписуються.
- [ ] 👤 Анти-абуз: strike-и за 30 днів (👤 7.6, [D37](decisions/D37-anti-abuse-strike-window.md)) — ⚠️ зараз за весь час, і тестувальники натраплять на вічний блок першими. Кнопка розблокування — M2.6.
- [ ] `CLAUDE.md`, `architecture.md` — розділ коментарів.

**Тести:** unit — сплющення й порядок; e2e — відповідь на відповідь → той самий рівень і `replyToUserId`; видалили відповідь → інші лишились; видалили корінь → гілка схована; редагування на 16-й хвилині → 403; пачка лайків з `myReaction`; strike 31-денної давності не рахується.
**Готово, коли:** коментарі новини виглядають і поводяться як на YouTube; на сторінці — один запит на порцію коментарів.

## 8. Definition of Done

### Сторінка (👤 12.5 — замінює окремі етапи «Mobile» і «SEO»)
- [ ] 320 / 768 / 1280 px без горизонтального скролу (адаптивність «легка» — редизайн у M3.6)
- [ ] `generateMetadata`: title, description, canonical, hreflang
- [ ] 404 для неіснуючої сутності (`fetchQuery` + `notFound()`)
- [ ] Скелетон завантаження
- [ ] Обидві мови інтерфейсу (`en`, `uk`)
- [ ] ⭐ Дати — лише `useDateTimeFormat` / `formatDateTime`
- [ ] ⭐ Базова доступність: клавіатура, `alt`, контраст, `aria` у меню
- [ ] ⭐ Без помилок у консолі браузера й без помилок гідрації

### Ендпоінт API ⭐
- [ ] DTO з межами для кожного параметра (🧭 п. 6)
- [ ] Response DTO + опис у Swagger: метод контролера повертає `Promise<…Dto>`, коди помилок — `@throws` у JSDoc, доступ — `@AuthRequired()` / `@AdminOnly()`; `pnpm gen:api-types`
- [ ] Prisma `select`, не `include`
- [ ] Помилки з кодами (`POST_NOT_FOUND` …)
- [ ] e2e: успіх, права (401 / 403), 404, невалідні дані (400) — з `expectMatchesContract` (без перевіреного успіху повний прогін e2e падає — M1.4.9)

### Етап ⭐
- [ ] Тести змістовні й зелені; ручний сценарій пройдено
- [ ] План оновлено (чекбокси, «Зроблено»); `architecture.md` / `CLAUDE.md` — якщо змінилась архітектура
- [ ] Запропоновано назву коміту (Conventional Commits) і підсумок; коміт робить власник

## 9. Процес (детально — [`rules/process.md`](rules/process.md))

- 👤 Гілка на етап → PR у `master`; коміт після готової роботи; коміти робить власник, AI пропонує назву й підсумок.
- 👤 План оновлює AI після кожного етапу.
- 👤 Після підтвердженого кінця етапу — бриф наступного: що й навіщо, що треба знати чи вирішити, ризики, як перевіримо.
- 👤 Тести — лише змістовні, із запуском окремо для модуля.
- 👤 Складний етап → під-етапи по черзі.
- 👤 Якщо щось не вказано — рішення за найкращими практиками, позначене ⭐.

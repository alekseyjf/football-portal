# Документація 12Yards

| Файл | Що там | Коли читати |
|---|---|---|
| [`football-plan.md`](football-plan.md) | Дорожня карта: мета, віхи M1–M4, етапи з чекбоксами, Definition of Done, повний чекліст зробленого (M0) | Перед кожним етапом |
| [`decisions/`](decisions/README.md) | Реєстр рішень з обґрунтуваннями: історія схеми v5 (D1–D20, P*, R*, 🧭) і нові рішення (D21+) | Коли треба зрозуміти, **чому** зроблено саме так |
| [`rules/`](rules/) | Правила: чистий код і архітектура, backend, frontend, безпека, стиль коду, редакція, процес | Перед написанням коду; нове позначено ⭐ |
| [`architecture.md`](architecture.md) | Як влаштовано систему: схема, football-синк, ендпоінти, карта файлів | Розбір коду |
| [`open-questions.md`](open-questions.md) | Питання, які треба вирішити перед конкретним етапом, з рекомендаціями | Перед етапом, що на них посилається |
| [`backlog.md`](backlog.md) | Технічний борг і відкладене — з причиною й тригером | Планування наступних етапів |
| [`ideas.md`](ideas.md) | Ідеї без рішення | Коли шукаємо, що робити далі |
| [`archive/`](archive/README.md) | Старі плани (v1, v4.7, проміжний план v5) — історія, **не** план | Щоб зрозуміти, від чого відмовились |

## Позначки в плані

| Позначка | Значення |
|---|---|
| 👤 | Рішення власника |
| ⭐ | Рекомендація: так роблять сильні команди (поруч — «чому») |
| ❓ | Уточнити перед виконанням (`open-questions.md`) |
| ⚠️ | Розбіжність між очікуванням і кодом |

## Як оновлювати
- Після кожного етапу AI оновлює `football-plan.md` (чекбокси, «Зроблено»), за потреби — `backlog.md`, `ideas.md`, `open-questions.md`.
- Нове архітектурне рішення — файл `decisions/D<N>-….md` (шаблон — `decisions/README.md`).
- Стан проєкту живе **лише** в плані; README репозиторію — опис і запуск; `CLAUDE.md` — контекст для AI.
- Документи в `docs/` — з кінцями рядків LF.

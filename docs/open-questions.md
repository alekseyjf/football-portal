# ❓ Відкриті питання

> Питання, які треба вирішити **перед** конкретним етапом. До кожного — ⭐ рекомендація. Коли питання вирішено — рішення переїжджає в `decisions/` (або в пункт плану), а тут позначаємо ✅ і посилання.
> ⏰ — коли повертаємось. Джерело — номер питання з обговорення плану (2026-10-06).
> Номери OQ стабільні (на них посилається план), тому в списку вони згруповані за віхою, а не за порядком.

## Перед M1 (тестовий реліз)

### OQ-1 · Теги у фільтрах · ⏰ перед M1.4.6
- **Питання:** (а) кілька вибраних тегів — новини з **будь-яким** із них чи з **усіма** одразу; (б) чи потрібна окрема сторінка тегу; (в) чи можна створити новий тег прямо з форми поста. 👤 У10 — «повернутись перед реалізацією».
- ⭐ **Рекомендація:**
  - всередині одного фільтра — «будь-який» (АБО), між різними фільтрами (тег + ліга + клуб) — «і». Це стандарт фасетного пошуку (так фільтрують Amazon, Booking): вибір ще одного тегу розширює список, а не обнуляє його;
  - окрема індексована сторінка тегу `/{locale}/news/tag/{slug}` з власним заголовком для Google; комбінації фільтрів на `/news?…` — `noindex, follow` + canonical на `/news`, інакше кожна комбінація стає дублем у пошуку;
  - теги — і на окремій сторінці адмінки, і «створити» прямо з пікера у формі (як у WordPress і Ghost).

### OQ-2 · Відео в новинах · ⏰ перед M1.6
- **Питання:** як вбудовувати відео (👤 У13 — «вирішимо, коли дійдемо»).
- ⭐ **Рекомендація:** на старті лише YouTube; основне відео — поле `videoUrl` (плеєр під обкладинкою), а YouTube-посилання окремим рядком у тексті теж стає плеєром. Плеєр — «фасад»: спершу картинка-прев'ю, iframe з `youtube-nocookie.com` вантажиться лише після кліку (повний iframe тягне сотні КБ JS і псує швидкість сторінки — так радить Lighthouse).

### OQ-3 · Модель коментарів як на YouTube · ⏰ перед M1.7
- **Питання:** підтвердити модель і сортування ([D27](decisions/D27-youtube-style-comments.md)).
- ⭐ **Рекомендація:** усі відповіді гілки — `parentId = rootId`; кому відповіли — `replyToUserId`; наявні дані «сплющити» міграцією. Сортування коренів — «Популярні» за замовчуванням (як на YouTube) + перемикач «Нові». Порція — 20 коренів, відповідей — 10.

### OQ-4 · Markdown і наявні пости · ⏰ перед M1.4.3
- **Питання:** у наявних постах простий текст з одинарними переносами рядків; у Markdown одинарний перенос не створює новий рядок — абзаци «злипнуться».
- ⭐ **Рекомендація:** подивитися наявні пости; якщо їх кілька — поправити вручну (подвійні переноси між абзацами) і лишити стандартний Markdown. `remark-breaks` (кожен перенос = новий рядок) — лише якщо редакції так зручніше.

### OQ-5 · Локальна БД для e2e-тестів · ⏰ перед M1.3
- **Питання:** де запускати e2e локально без Docker ([D30](decisions/D30-testing-and-local-env.md)).
- ⭐ **Рекомендація:** Postgres з Homebrew (`brew install postgresql@17`, окрема БД `football_e2e`) — швидко, ізольовано, нічого не ламає. Альтернатива без встановлення — окрема схема в dev-Supabase (`?schema=e2e`), але повільніше й залежить від мережі. У CI — тимчасовий Postgres-контейнер GitHub Actions у будь-якому разі.

### OQ-6 · CSRF · ⏰ перед M1.11 (👤 9.1 — активне питання)
- **Контекст:** cookies `SameSite=Lax`, мутації — лише POST / PUT / DELETE з JSON (CORS preflight), суворий CORS — класичний CSRF уже ускладнено. На тесті — один origin (rewrites, [D31](decisions/D31-test-environment.md)).
- ⭐ **Рекомендація:** для мутацій — перевірка Fetch Metadata (`Sec-Fetch-Site: same-origin` / `same-site`) і `Origin` (OWASP: «defense in depth» поверх SameSite; так захищається Google). Токен (double-submit) — лише якщо з'явиться клієнт з іншого сайту. Пакет `csurf` застарів — не використовувати.
- Чекліст з архіву (`archive/csrf-samesite-checklist.md`): `SameSite` ✅, `Secure` на проді ✅ (за `NODE_ENV`), CORS з env без `*` ✅ — лишилось саме рішення про перевірку мутацій.

### OQ-7 · Хостинг тест-сервера · ⏰ перед M1.11
- **Вимоги:** Docker для API; інстанс, що не засинає (cron синку кожні 2 год); безкоштовно або майже; регіон — поруч із БД Supabase.
- **Варіанти** (умови й ціни змінюються — перевірити в момент вибору):
  - web і admin — **Vercel Hobby** (безкоштовно; лише некомерційне використання — для тесту ок);
  - API — **Railway** (~$5/міс, не засинає, Docker) · **Fly.io** (оплата за використання, малий інстанс ~$2–5/міс) · **Render Free** (безкоштовно, але засинає через ~15 хв без запитів, холодний старт до хвилини — cron у процесі не виконається) · **Google Cloud Run** (щедрий безкоштовний рівень, масштабується до нуля — cron через Cloud Scheduler) · **Oracle Cloud Always Free** (безкоштовна VM, що не засинає, але сервер адмініструєш сам).
- ⭐ **Рекомендація:** Vercel (web, admin) + API на Railway або Fly.io — найпростіше й без «засинання». Якщо строго $0 — Render Free + cron через GitHub Actions `schedule`, який викликає захищений ендпоінт синку (секретний токен у заголовку).

### OQ-8 · Розділити dev і test БД · ⏰ перед M1.11
- **Контекст:** 👤 тест-сервер використовує поточну БД Supabase.
- ⭐ **Рекомендація:** поточна БД (з даними) стає тестовою; для локальної розробки — новий безкоштовний проєкт Supabase (на безкоштовному рівні — 2 активні проєкти) або локальний Postgres (OQ-5). Інакше локальна міграція чи експеримент ламає сервер тестувальників.

## Перед M2 (розвиток на тесті)

### OQ-16 · Аналітика · ⏰ після тестового релізу (M2.9)
- ⭐ **Рекомендація:** Plausible (~$9/міс) або Umami (безкоштовна хмара / self-host) — без cookies, тож без банера згоди. GA4 — лише якщо знадобиться реклама Google (тоді банер згоди обов'язковий).

### OQ-17 · Що дає тариф football-data · ⏰ перед M2.2
- **Питання:** від тарифу залежить, що взагалі можна показати.
- **Перевірити реальними запитами** (як у Фазі 5.1): бомбардири (`/competitions/{code}/scorers`) і склади команд (`/teams/{id}`) — ймовірно, є на безкоштовному тарифі; картки, склади на матч і події (голи, заміни) — лише на платних; затримка live-рахунків; умови комерційного використання.
- ⭐ **Рекомендація:** чого немає на безкоштовному — в `ideas.md` до рішення про платний тариф (M4) або іншого провайдера.

### OQ-18 · Майбутні пари плей-оф (TBD) · ⏰ перед M2.11
- **Контекст:** синк пропускає матчі без визначених учасників → у БД немає майбутніх раундів плей-оф (🧭 п. 7).
- ⭐ **Рекомендація:** `homeClubId` / `awayClubId` → nullable (адитивно) + синк створює TBD-матч і оновлює після жеребкування; сітка — колонки стадій (провайдер не дає зв'язків «переможець → наступний матч»).

### OQ-19 · Формат статистики лайків · ⏰ перед M2.6
- ⭐ **Рекомендація:** таблиця з сортуванням (лайки, дизлайки, коментарі, дата) + топ-10 за тиждень; графіки — пізніше, коли буде трафік.

### OQ-20 · Сповіщення «вам відповіли» · ⏰ перед M2.8
- ⭐ **Рекомендація:** спершу в застосунку (лічильник у навбарі + список); листи — після налаштування пошти (M3.3), з відпискою одним кліком.

### OQ-23 · Календар: вигляд · ⏰ перед M2.3
- ⭐ **Рекомендація:** день (як `/matches`) + вибір дати місячним календарем із позначками днів, де є матчі; тиждень — пізніше, якщо попросять.

## Перед M3 (підготовка до проду)

### OQ-9 · Домени й топологія проду · ⏰ M3.1 (👤 10.3, 14.2)
- ⭐ **Рекомендація:** власний домен із піддоменами: `12yards.com` (web), `api.12yards.com`, `admin.12yards.com` — same-site cookies, API доступне іншим клієнтам (мобільний застосунок), API масштабується й деплоїться окремо. DNS — Cloudflare (безкоштовно: CDN, захист від DDoS, Access, Turnstile).

### OQ-10 · Закрити адмінку · ⏰ тест — M1.11, прод — M3.2 (👤 10.5)
- **Що це означає:** вхід в адмінку вже вимагає ролі ADMIN; «закрити» — щоб сторонні не бачили навіть форми входу.
- ⭐ **Рекомендація:** тест — той самий Basic Auth, що й на сайті; прод — Cloudflare Access (вхід через пошту, безкоштовно до 50 людей) + 2FA адміна (M3.2).

### OQ-11 · Транзакційний пулер Supabase (`:6543`) · ⏰ M3.5 (👤 13.7)
- **Контекст:** запит на «мертвому» сокеті висить ~12–15 хв (відтворено без нашого коду); через session-пулер (`:5432`) прогони чисті.
- **Чекліст власника:**
  - Prisma з transaction pooler — перевірити `pgbouncer=true` і `connection_limit` у `DATABASE_URL` (з driver adapter `PrismaPg` — звірити з документацією Prisma 7);
  - міграції — через `DIRECT_URL` (✅ уже так, `prisma.config.ts`);
  - довгі й незакриті інтерактивні транзакції тримають з'єднання — `timeout` на транзакціях і `statement_timeout` на БД;
  - синк не тримає одну транзакцію на весь прогін — пише чанками (✅ уже так, по 50 матчів);
  - один `PrismaClient` на процес (✅ уже так, `PrismaModule`);
  - відтворити зависання, подивитися `pg_stat_activity` — клієнт чи пулер; `keepAlive`, `connectionTimeoutMillis`, `query_timeout` у `PrismaPg`.

### OQ-12 · Підтвердження пошти й «Забули пароль» · ⏰ M3.3 (👤 7.8, 8.5)
- **Питання:** до проду чи вже на проді; коментувати й лайкати без підтвердження не можна (👤 7.8) — коли це вмикаємо.
- ⭐ **Рекомендація:** до відкриття публічної реєстрації на проді: без підтвердження реєстрація на чужу пошту й перевірка «чи зареєстрована адреса» (enumeration) лишаються відкритими.

### OQ-13 · Captcha · ⏰ M3.2 (👤 8.7)
- ⭐ **Рекомендація:** Cloudflare Turnstile (безкоштовно, без «знайди світлофори») на реєстрації; на вході — лише після кількох невдалих спроб.

### OQ-14 · Вхід через Google (OAuth) · ⏰ M3.3 (👤 8.4)
- ⭐ **Рекомендація:** разом із підтвердженням пошти (Google-акаунт уже має підтверджену пошту); таблиця `AuthAccount`, `passwordHash` → nullable.

### OQ-15 · Банер на головній з адмінки · ⏰ M3.6 (👤 У11)
- **Питання:** що таке банер — промо, реклама, головна новина; як налаштовується.
- ⭐ **Рекомендація:** вирішити разом із рекламною стратегією (M4): слот на головній, керований з адмінки (зображення, посилання, період показу, мова).

### OQ-21 · Дублі сторінок, коли додамо нову мову · ⏰ M3.7 (👤 4.1)
- ⭐ **Рекомендація:** сторінка без перекладу — `canonical` на EN-версію й без `hreflang` для цієї мови ([D34](decisions/D34-seo-multilingual.md)); або взагалі не показувати мовну версію без перекладу (404 + перемикач мови веде на EN).

### OQ-22 · Платні сервіси на проді · ⏰ M3.1 (👤 1.5)
- **Орієнтир** (ціни приблизні — перевірити перед продом):
  - домен — ~$10–15 на рік;
  - Vercel Hobby — лише некомерційне використання; з рекламою — Pro (~$20/міс) або власний сервер у Docker;
  - Supabase Free засинає після тижня без активності й не має щоденних бекапів → Pro (~$25/міс);
  - API — інстанс, що не засинає, ~$5–20/міс;
  - пошта — Resend / Postmark: безкоштовно — тисячі листів на місяць, далі ~$15–20/міс;
  - безкоштовно надовго: Cloudflare (DNS, CDN, Turnstile, Access), Sentry (базовий рівень), UptimeRobot / Better Stack, Cloudflare R2 (~10 ГБ);
  - аналітика — Plausible ~$9/міс або Umami;
  - football API — платний тариф, коли знадобляться live і детальна статистика (M4).

### OQ-24 · Логотип і бренд · ⏰ M3.6 (👤 У23)
- **Потрібно від власника:** файл логотипу (бажано SVG), фірмові кольори, написання назви в інтерфейсі («12Yards»).
- До того — текстовий логотип.

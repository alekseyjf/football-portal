# D50 — Редагування новини в адмінці: у `PUT` — лише змінене, статуси — за станом новини

- **Статус:** ✅ прийнято · 2026-10-23 · 👤 рішення власника (бриф M1.5.2: збережений переклад UK, поле slug, незбережені зміни, статуси, тіло `PUT`, що після збереження, пояс біля дати; етап — двома під-етапами) + ⭐ деталі · ✅ редагування, статуси, видалення — M1.5.2.1 · ✅ список і незбережені зміни — M1.5.2.2 (👤 бриф M1.5.2.2: вікно-питання, «Вийти», фільтр, пошук і адреса, повернення до списку, прапорець після збереження, сесія скінчилась; 👤 правки перед комітом: порожній slug живої новини, повернення у вкладку, після створення — сторінка редагування, перехід часу, обрізання країв)
- **Етап:** M1.5.2.1 (сторінка редагування), M1.5.2.2 (список новин, незбережені зміни)
- **Уточнює:** [D24](D24-news-url-slug-number.md) — поле slug у редагуванні; [D43](D43-archived-posts.md) — Archived як «зняти з публікації»; [D44](D44-cover-image-alt-credit.md), [D26](D26-post-sources.md) — що форма надсилає про обкладинку й джерело; [D47](D47-admin-posts.md) — новина для форми й refetch; [P3-5](v5-content.md) — переклад не видаляється

## Контекст
`PUT /posts/{id}` (M1.4) — частковий: не передане поле не змінюється, `null` прибирає; переклад — upsert за мовою, і кожен — повністю (заголовок, анонс, текст); переданий масив `tagIds` / `clubIds` / `competitionIds` замінює прив'язки; видалити переклад не можна (P3-5). Форма створення (M1.5.1) надсилає все заповнене. Якби редагування так само надсилало всю форму, кожне збереження перезаписувало б те, чого редактор не змінював (і те, що встиг змінити інший адмін), стирало б зв'язки, задані через Swagger (у формі їх ще немає — M1.5.3), а старий опис фото йшов би як опис нового.

## Рішення

### Тіло `PUT` — з різниці
- 👤 `toUpdatePostRequest(saved, current)`: `saved` — поля збереженої новини (`toPostFormValues`), `current` — форма після перевірки; порівнюємо **значення**, а не `dirtyFields` React Hook Form (поле, змінене й повернуте назад, — не зміна). Очищене поле — `null`.
- 👤 Переклад мовою — лише якщо змінилось його поле: заголовок, анонс, текст чи опис фото; надсилається повністю, як того хоче API.
- 👤 Нова адреса обкладинки — разом з описом кожною мовою й підписом (старі API не переносить, D44), навіть якщо текст той самий; та сама адреса — лише змінений опис чи підпис; прибрана — `coverImageUrl: null`, опис і підпис API прибере сам. ⭐ Джерело — за тим самим правилом: інша адреса — разом з назвою, `sourceUrl: null` прибирає джерело цілком (D26: назва — про конкретну адресу).
- 👤 `tagIds`, `clubIds`, `competitionIds`, `videoUrl` форма не надсилає ніколи (вибір зв'язків — M1.5.3, відео — OQ-2).
- ⭐ Публікація — пара «статус + дата»: змінилось хоч одне — надсилаємо статус, для розкладу — ще й дату. Publish now, Unpublish, Publish again — без дати: її вирішує API (опублікована — наявна минула або зараз; архівна повертається зі своєю, P3-2).
- ⭐ Slug — коли адреса зміниться; вписаний — ще й тоді, коли змінився англійський заголовок. *Чому:* без явного slug-а API дав би чернетці slug нового заголовка (D24) і загубив би вписаний; для новини з датою це повтор поточного slug-а — API його не змінить.
- ⭐ Схема форми обрізає пробіли по краях у кожному текстовому полі — *чому:* API зберігає без них, тож пробіл у кінці не стає «зміною», а тіло запиту береться як є. 👤 (правки перед комітом) Лише краї всього значення: усередині не чіпаємо — у Markdown два пробіли в кінці рядка означають перенос. Текст, збережений до того, як API почав обрізати (до фази 3), форма відкриває вже без країв (`toPostFormValues`): він не стає «зміною» — у `PUT` не йде переклад, якого редактор не торкався. Обидва правила — unit-тести.

### Статуси в UI — 👤 за станом новини
| Новина зараз | Варіанти у формі |
|---|---|
| нова, чернетка, запланована, що чекає своєї дати | Draft · Publish now · Schedule |
| на сайті (і запланована, чий час настав, — D47) | Published · Unpublish (Archived) |
| архівна | Draft · Publish again (зі своєю датою) · Archived |

- 👤 Опублікованій — без Draft: Draft стирає дату, і повторна публікація підняла б стару новину як свіжу. Unpublish = Archived ([D43](D43-archived-posts.md)): з сайту зникає, дата лишається, «Publish again» повертає новину на її місце в стрічці. Архівну в чернетки — можна, свідомо: підказка попереджає, що опублікована знову вона вийде як нова.
- 👤 API не змінюємо: правило — у формі (`publicationOptionsFor`), Swagger лишається з повним набором переходів.
- 👤 (правки перед комітом) «На сайті» форма визначає лише за `isLive` з API, не за статусом: у запланованої, чий час настав, `GET /posts/admin/{id}` віддає `status: SCHEDULED` і `isLive: true` (статус ніхто не переписує — вона виходить сама, без cron). За `isLive` — варіанти статусу (лише Published / Unpublish), статус у формі (Published, тож без змін у `PUT` він не йде, і новина лишається на сайті), порожня адреса й попередження 308. Перевірено наживо: заплановано через форму на +1 хв → час настав → форма жива.

### Збережений переклад, slug, дата розкладу
- 👤 Збережену українську версію очистити не можна (P3-5): поля обов'язкові, як англійські, помилка — «already saved and can't be removed — fix the text instead», запит не йде; підказка вкладки — «saved: it can be corrected, but not removed». *Чому:* тихо «незмінений» переклад після очищення полів збив би редактора. Видалення перекладу — [`backlog.md`](../backlog.md).
- 👤 Поле slug: у чернетки — порожнє, якщо slug дорівнює slug-у англійського заголовка (адреса й далі йде за заголовком), інакше — поточний (вписаний при створенні); у новини з датою — поточний. Під полем — адреса з номером новини; попередження «стара адреса перенаправить (308)» — лише для живої (`isLive`).
- 👤 (правки перед комітом) У живої новини поле адреси порожнім бути не може: помилка біля поля «The address of a published post can’t be empty — keep “…” or type a new one», запит не йде — *чому:* порожнє поле — «адреса з англійського заголовка», тобто тиха нова адреса новини, посилання на яку вже розійшлись. ⭐ Правило — у схемі форми (новина «на сайті» — `isLive` збереженої, у контексті схеми), не в API — як і статуси за станом новини (вище); у живої поле адреси — без «(optional)», а попередження 308 — лише для вписаної нової адреси.
- 👤 Біля дати розкладу — пояс редактора: «(Kyiv, UTC+3)». ⭐ Зсув — на **вибрану** дату: 23 жовтня Київ на UTC+3, а 26-го — уже на UTC+2. Перетворення поля `datetime-local` ↔ ISO бере пояс явно (`lib/editorDateTime.ts`), тож перехід часу перевіряють unit-тести; біля переходу — як браузер: година, що повторюється, — перша з двох, якої немає — зсувається вперед. Стара назва ICU `Europe/Kiev` — підписуємо «Kyiv».
- 👤 (правки перед комітом) Перехід часу в Києві — unit-тести на дві дати: 25.10.2026 03:30 буває двічі — обрано першу, ще за літнім часом (`00:30Z`, «Kyiv, UTC+3»), у полі й у списку — 03:30; 28.03.2027 03:30 не існує — зсув уперед, новина вийде о 04:30 за літнім часом (`01:30Z`), після збереження поле й список показують 04:30. ⭐ Під полем — пояснення (`scheduleTimeNote`): «No such time … goes live at 28 Mar 2027, 04:30 (Kyiv, UTC+3)» / «This time happens twice … the first one is used» — *чому:* поле `datetime-local` не покаже, що часу немає, а пояс біля поля («UTC+3») без пояснення натякав би на іншу мить, ніж збережеться.
- ⭐ Збережений розклад без змін на «в майбутньому» не перевіряється — *чому:* його час міг настати, поки форма відкрита (новина вже вийшла сама), а в запит незмінена дата не йде.

### Після збереження
- 👤 Інвалідувати список і новину, перечитати новину (відповідь `PUT` — без текстів), форма — зі свіжих даних, лишаємось на сторінці.
- ⭐ Форма й варіанти статусу — від **знімка** збереженої новини (стан сторінки), а не від даних запиту — *чому:* фоновий refetch (повернення у вкладку) інакше зсунув би базу порівняння й варіанти статусу під рукою редактора. Дані вже є — форма лишається, навіть коли фоновий refetch упав: збій мережі не прибирає незбережений текст. 👤 (правки перед комітом) Перевірено наживо: почати редагування → інша вкладка → повернутись через хвилину (refetchOnWindowFocus перечитав новину) → набраний текст на місці, а правка іншого адміна тим часом (українська версія) збереглась — `PUT` надіслав лише змінене. Контрольний прогін — форма від даних запиту — губить набраний текст.
- ⭐ Save неактивна, доки немає змін; після збереження — «All changes saved» — *чому:* так у Strapi й Decap CMS, і повторне «збереження без змін» не шле запит.

### Видалення
- 👤 Soft delete з підтвердженням. ⭐ Нативний `<dialog>` (`showModal`): фокус стає на Cancel (безпечна дія першою), Esc закриває, сторінка під діалогом неактивна; після видалення — список новин, новина зникає з кешу (сторінка не перечитує видалену).

### Список новин (M1.5.2.2)
- 👤 Стан — в адресі: `/dashboard/posts?status=&search=&page=`. Фільтр за статусом — вкладки-посилання `?status=` (нова вкладка, «Назад»), без лічильників: API їх не віддає, а п'ять запитів заради чисел — забагато (одним запитом — [`ideas.md`](../ideas.md)). Новий фільтр чи пошук — з першої сторінки.
- 👤 Пошук — пауза 300 мс (Enter — одразу), параметр `search`, як в API; без пробілів по краях, до 100 символів; порожній прибирає параметр (на `search=` API відповідає 400).
- 👤 Адресу змінює `history.pushState` (фільтр, сторінка) / `replaceState` (пошук: пауза в наборі не стає кроком «Назад»), а не `router.push` / `replace` — Next синхронізує з ними `useSearchParams` без запиту до сервера. Розбір адреси — чиста функція `parsePostListParams` з unit-тестами: невідомий статус — усі, некоректна сторінка — перша, задовгий пошук обрізано.
- 👤 Попередня сторінка лишається видимою (приглушена) лише при переході на іншу сторінку того самого фільтра; новий фільтр чи пошук — «Loading posts…»: старі рядки під новим фільтром виглядали б його результатом. Сторінки вже немає (новини видалили, старе посилання) — порожній стан із посиланням на останню, а не тихий перехід.
- 👤 Повернення: список пише свою адресу в sessionStorage (`lastPostListHref`); «← All posts», Cancel і перехід після видалення ведуть туди, без збереженої — список без фільтрів. `router.back()` не використовуємо: «назад» зі сторінки, відкритої за адресою, вивів би з адмінки.
- 👤 Рядок на 320 px: заголовок на всю ширину й обрізається (`min-w-0`, `truncate`), дії — під ним до 640 px. Дата — `formatEditorDateTime` (пояс редактора), мови — EN ✓ / UK ✗.
- 👤 (правки перед комітом) Після створення — сторінка редагування нової новини (`router.replace`: «Назад» не повертає до порожньої форми) з повідомленням «✓ Draft created»; ⭐ за статусом, з яким створили, — «Post created and published» / «Post created and scheduled», до першого збереження. Сторож мовчить (`allowLeave` перед переходом). ⭐ Позначка «щойно створена» — у пам'яті вкладки (`useCreatedPostNotice`), а не в адресі (`?created=1`) — *чому:* перезавантаження чи скопійоване посилання повідомлення не повторять. Пункт меню «Пости» — список без фільтрів.
- ⭐ Сторінка списку — динамічна (`connection()`), а не статична, як планували в брифі — *чому:* Next 16.2 кешує статичну сторінку під адресою з query її першого завантаження ([vercel/next.js#92187](https://github.com/vercel/next.js/issues/92187)): відкрита як `?status=SCHEDULED`, вона підставляла цей фільтр у кожен перехід на `/dashboard/posts` без query — меню, після створення, «← All posts» у стан «All» (відтворено наживо на `next start`; на сторінці дашборду — так само, тож не наш код). Динамічна рендериться на сервері при кожному переході в список — порожня оболонка, дані однаково вантажить React Query; фільтр, пошук і сторінки — як і планували, `pushState` без запитів. Статичну можна повернути, коли Next виправить ваду ([`backlog.md`](../backlog.md)).
- ⭐ «Edit» у рядках — без prefetch — *чому:* кожен фільтр і сторінка дають до 20 нових посилань, по два запити prefetch на кожне (виміряно: 40 на перегляд списку), а вміст сторінки редагування однаково вантажить React Query. Посилання на інший стан списку — `PostListLink`: справжня адреса (нова вкладка, копіювання), клік — `pushState`, без prefetch.
- ⭐ Для екранного диктора: «Edit» / «View on site» — з назвою новини (інакше двадцять однакових «Edit»), відсутня мова — «UK (missing)», кількість знайдених — `role="status"`.

### Незбережені зміни (M1.5.2.2)
- 👤 Один сторож на адмінку через контекст: `UnsavedChangesProvider` (кореневий layout), форма — `useUnsavedChangesGuard(isDirty)`, і на створенні, і на редагуванні. Питають посилання (`onNavigate`, і в меню), Cancel і «Вийти» (вихід веде на логін — текст пропав би так само); закриття й перезавантаження вкладки зупиняє `beforeunload` — слухач лише поки є зміни (з ним браузер гірше кешує сторінку для «Назад»). Кнопку «Назад» браузера (`popstate`) не перехоплюємо — перехоплення history API крихке. Локальна копія чернетки в `localStorage` — [`backlog.md`](../backlog.md).
- 👤 Питання — нативний `confirm()` (синхронний — `onNavigate` вирішує одразу), лише через одну функцію `confirmDiscardChanges()` у сторожі (`lib/unsavedChanges.ts`): свій `<dialog>` пізніше — заміна в одному місці.
- 👤 Після вдалого створення чи видалення — синхронний прапорець «вихід дозволено» (`allowLeave`) перед `router.push`, не стан React: форма ще «брудна», поки відкривається список (unit-тест: питання тоді немає; нова зміна форми вмикає його знову). Редагування після збереження лишається на сторінці: форма скидається до збереженого, і сторож замовкає сам.
- 👤 Сесія скінчилась (refresh відхилено), а у формі незбережені зміни — на `/login` адмінка не переводить: форма лишається, помилка «Your session has expired — log in again in a new tab, then click “Save changes” here once more.» (на створенні — «Create post»). Без змін — як і раніше, на логін.
- ⭐ Посилання адмінки — лише `AdminLink` (`next/link` + `onNavigate` сторожа), `next/link` напряму забороняє ESLint (`no-restricted-imports`) — *чому:* нове посилання (сторінка тегів у M1.5.3) інакше непомітно обійшло б сторож. Ctrl/Cmd+клік і зовнішні адреси `onNavigate` не викликають — нова вкладка нічого не губить.
- ⭐ Стан сторожа — у змінних, а не в стані React — *чому:* посилання читають його синхронно, в мить кліку, а зміна форми не перерендерює всю адмінку.

## Як роблять сильні команди
- Ghost Admin API: `PUT /posts/{id}/` — лише змінені поля разом з `updated_at` (оптимістичне блокування); WordPress REST — частковий `POST /wp/v2/posts/{id}`.
- Опублікований матеріал знімають, не стираючи дати (WordPress: «Switch to draft» з попередженням; у нас — Archived, дата лишається).
- Strapi, Decap CMS: Save неактивна без змін.
- Ghost, WordPress: попередження перед виходом зі сторінки з незбереженою новиною; документація Next («Blocking navigation») — той самий шаблон: контекст + своє посилання з `onNavigate` + `confirm`.
- Списки адмінок (WordPress «Posts», GitHub issues): фільтр, пошук і сторінка — в адресі, посилання на список відкриває той самий стан.

## Наслідки
- Дві вкладки, що міняють різне (різні мови, обкладинку, джерело, статус), не перезаписують одна одну. Одну мову переклад надсилає повністю — тут перемагає останнє збереження; оптимістичне блокування — [`backlog.md`](../backlog.md) (тригер — другий редактор).
- Новина, що не проходить правила публікації (опублікована з обкладинкою без підпису — так лишились пости до M1.4.4), не збережеться, доки редактор не допише бракуюче, — як і в API (D44).
- Переклад вимкненою мовою форма не показує й не надсилає (D47).
- Unit-тести (Vitest, адмінка): тіло `PUT` — кожне правило (`postFormEdit.test.ts`), поля форми з новини, варіанти статусу (`publicationOptions.test.ts`), правила збереженої новини в схемі (і порожня адреса живої), обрізання лише країв і текст, збережений до обрізання, перетворення дати й пояснення біля поля в ніч переходу часу (`lib/editorDateTime.test.ts`); адреса списку ↔ стан і запит до API, збережена адреса повернення (`lib/postListParams.test.ts`); сторож — питання, `allowLeave`, `beforeunload` (`lib/unsavedChanges.test.ts`).
- Список новин — динамічна сторінка: кожен перехід у список — рендер на сервері (оболонки, без даних).

## Розглянуті альтернативи
- Уся форма в `PUT` (як у створенні) — відхилено: перезапис чужих змін, стерті зв'язки, старий опис фото як опис нового.
- `dirtyFields` React Hook Form — відхилено 👤: «змінено й повернуто» лишається «брудним», а скидання форми й `setValue` роблять картину неточною; порівняння значень — одна чиста функція з тестами.
- Draft для новини на сайті — відхилено 👤 (дата стирається, повторна публікація — як нова).
- Правило статусів в API — відхилено: Swagger лишається повним інструментом адміна, форма дає лише безпечні переходи.
- Видалення перекладу в API (`null` у `PUT` чи окремий ендпоінт) — 👤 відкладено до потреби ([`backlog.md`](../backlog.md)).
- Пояс — зсув сьогоднішньої дати (`getTimezoneOffset`) — відхилено: розклад на дату після переходу часу зсунувся б на годину.
- Скинути форму перемонтуванням (`key`) після збереження — відхилено: губить відкриту вкладку мови й режим тексту; RHF `values` скидає форму на місці.
- Свій `<dialog>` замість `confirm()` — 👤 відкладено: навігацію довелося б скасувати й повторити вручну; заміна — в одній функції.
- `router.push` / `replace` для фільтра, пошуку й сторінок — відхилено 👤: зайвий запит до сервера на кожну зміну.
- Статична сторінка списку — відхилено ⭐ після перевірки наживо (Next #92187, розділ «Список новин»).
- Лічильники біля фільтра — 👤 відкладено ([`ideas.md`](../ideas.md)).
- Після створення — список (як у M1.5.1) — відхилено 👤: редактор продовжує роботу над новиною, а не шукає її в списку.
- Позначка «щойно створена» в адресі (`?created=1`) — відхилено ⭐: повідомлення повторювалось би після перезавантаження й у скопійованому посиланні.

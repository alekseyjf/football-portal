# D55 — Головна: порядок у DOM, головна новина й шість, блоки незалежні, стрічка матчів дня

- **Статус:** ✅ прийнято · 2026-10-26 · 👤 рішення власника (бриф M1.6.3 і відповіді: головна новина + 6, порядок — у DOM, стрічка матчів дня до 40 з прокруткою, оновлення рахунків — лише своєю API, блоки деградують незалежно, SEO головної; пояс — cookie, кеш — M2.12; закріплення — окремим під-етапом M1.6.4) + ⭐ деталі · ⏳ M1.6.3
- **Етап:** M1.6.3 (головна), M1.6.4 (головну новину обирає редактор — D56), M1.8 (canonical, hreflang), M1.10.2 (браузерні e2e), M2.12 (кеш і пояс)
- **Уточнює:** P5b-2 — ліга сайдбару за замовчуванням ([v5-football](v5-football.md)); [D48](D48-competition-in-play.md) — турнір «у грі»; [D52](D52-news-feed.md) — картка новини й вкладки ліг; [D35](D35-caching-measure-first.md) і 🧭 п. 14 — кеш і пояс (без змін)

## Контекст
Головна — сайдбар ліги й шість карток. На телефоні перший екран займав банер-заглушка, а в DOM першим ішов сайдбар: новини над ним ставив CSS `order`, тож Tab і екранний диктор ішли не в тому порядку, що око. Перемикач ліг показував усі увімкнені турніри — завершений ЧС стояв серед ліг, що йдуть, а лігою за замовчуванням могла стати перша за `sortOrder`, навіть скінчена. Збій API давав рядок «Завантаження…» чи текст без «Спробувати ще». Матчів дня на головній не було.

## Рішення

### Порядок і розкладка
- 👤 **Порядок — лише в DOM**, без CSS `order`: прихований h1 → стрічка матчів на всю ширину → «Останні новини» → сайдбар (перемикач ліг, таблиця, тури). ⭐ На десктопі сайдбар **праворуч** — *чому:* лише так порядок на екрані збігається з DOM; ліворуч його можна поставити тільки через `order` чи розміщення в сітці, і тоді Tab ішов би інакше, ніж бачить око. Банер-заглушку прибрано.
- 👤 **Головна новина + 6**, далі «Усі новини →» на `/news`. Від 1024 px головна займає дві колонки з трьох і три ряди: поруч — три новини рядками з мініатюрою, під ними — три звичайні картки; 640–1023 px — головна на всю ширину й шість рядків у дві колонки; телефон — головна з великим фото й шість рядків.
- ⭐ **Одна картка з виглядом за місцем** (`NewsCard`, `layout`: `card` — стрічка, `lead`, `row`, `rowBelowDesktop`): класи вигляду — цілими рядками в одній таблиці (`NEWS_CARD_LAYOUT_CLASSES`; Tailwind склеєних з частин класів не бачить), її ж бере скелетон — розміри збігаються. *Чому не окремий компонент головної новини:* розтягнуте посилання, рубрика, дата й позначка перекладу — ті самі.
- 👤 **LCP — фото головної:** `loading="eager"` + `fetchpriority="high"` (у Next 16 `priority` застарів — як у стрічці, D52), решта — `lazy`. Заголовок головної — менший на телефоні (`text-xl`): на 320 px `text-2xl` обрізав звичайний заголовок на третьому рядку.
- Дані до M1.6.4 — `GET /posts?limit=7` (`homeNewsQueryOptions`): перша — головна, шість — під нею.

### Сайдбар
- 👤 **Перемикач — турніри «у грі» + обраний** (D48) — та сама функція, що вкладки `/news` (`inPlayLeaguesWithSelected`, `lib/football/in-play-leagues.ts`): обраний не в грі — на своєму місці, вимкнений — останнім.
- ⭐ **Ліга за замовчуванням — спершу «у грі»** (уточнює P5b-2, `lib/football/default-league.ts`): ліга з env, якщо вона «у грі» → перша «у грі» за `sortOrder` → не в грі жоден (міжсезоння) — env, якщо ліга активна, інакше перша активна → список ліг не завантажився — env як є. *Чому:* інакше після ЧС головна відкривалась би на турнірі, що скінчився.
- ⭐ Прихований h2 «Таблиця й тури» (структура заголовків сторінки); без дашборду — скелетон, помилка — **одне** «Спробувати ще» (дашборд і, якщо впав, список ліг) замість трьох повідомлень у таблиці й турах.

### Блоки незалежні (👤)
- Сервер чекає всіх запитів блоків (`Promise.allSettled` з `fetchQuery`): невдалий запит не гідрується, і клієнт вантажить його сам — скелетон тієї ж висоти (без зсуву макета), помилка — «Спробувати ще» лише в цьому блоці (`components/layout/BlockLoadError`). Показані дані невдалий фоновий refetch не замінює — як у стрічці.
- ⭐ **`error.tsx` — лише коли API недоступне для всіх запитів сторінки** (`isHomeApiDown`, `lib/home/home-blocks.ts`: мережа чи 5xx; 4xx — відповідь, а не збій: ліги з `?league=` немає — це покаже сайдбар). *Чому:* одне повідомлення замість трьох однакових, а сторінка-заглушка не віддається пошуку зі статусом 200: наживо — 500 і `noindex`, частковий збій — 200. `error.tsx` — у групі маршрутів `(home)`, як `(feed)` у стрічці: інакше він накривав би й інші сторінки мови.

### SEO (👤)
- Один h1 (прихований: «Футбольний портал: новини, матчі й таблиці»), h2 на кожен блок, картки — h3.
- JSON-LD `WebSite` (назва, адреса головної цією мовою, мова, видання) і `Organization` (назва, адреса) — той самий вузол видання, що `publisher` у `NewsArticle` (D53). ⭐ Без `SearchAction` — пошуку на сайті немає; логотип — з брендом (OQ-24).
- `title` (свій, не шаблон сайту), `description`, Open Graph (`type: website`, назва сайту). canonical, hreflang, `og:locale` — M1.8 (спільний хелпер, frontend Rule 14).

### Стрічка матчів дня (коміт 2)
- 👤 Усі матчі дня в поясі читача, у розмітці — до 40 (решта — «Усі матчі»); порядок — турнір (`sortOrder`, як на `/matches`) → статус (іде → попереду → завершився; перенесені й скасовані — у кінці турніру, з позначкою статусу) → час. Остання картка — «Усі матчі →» на `/matches` того самого дня.
- 👤 Сьогодні матчів немає — «Найближчі матчі · {дата}» (`GET /football/matches/next-kickoff?from=`), немає й таких — блоку немає.
- 👤 Прокрутка вбік (scroll-snap, край обрізаної картки видно), від 1024 px — кнопки ‹ ›; `role="region"` з назвою блоку й `tabindex="0"`, кожна картка — посилання; ⭐ «Пропустити матчі» перед стрічкою.
- 👤 Оновлення — 60 с, поки є матч у грі або матч, чий початок настав не більше 3 год тому, а статус — ще «заплановано»; без `aria-live`, без `live-touch`.

### Пояс і кеш (👤, без змін)
- Пояс — cookie `tz` (🧭 п. 14): сервер рендерить у поясі читача, «сьогодні» для матчів — теж; `<time dateTime>` — UTC з API.
- Кешу немає: усі запити web до API — `cache: 'no-store'`, сторінки динамічні — нова чи запланована новина з'являється з наступного відкриття, `revalidateTag` не потрібен. `<LocalTime>`, гео-пояс хостингу й кеш сторінок — M2.12 (D35).

## Наслідки
- Новини, таблиця й (з комітом 2) матчі не залежать одні від одних: впав один запит — решта сторінки працює.
- `NewsCard` має чотири вигляди; стрічка `/news` — без змін (`card`).
- Кожен новий блок головної — свій запит у `Promise.allSettled` і свій результат у `isHomeApiDown`.

## Розглянуті альтернативи
- **Порядок через CSS `order` (як було)** — Tab і екранний диктор ішли б за DOM, а не за екраном (WCAG 2.4.3).
- **Сайдбар ліворуч на десктопі** — лише з `order` чи розміщенням у сітці, тобто знову порядок екрана ≠ DOM.
- **Три повідомлення про помилку, коли API недоступне повністю** — шум і сторінка-заглушка зі статусом 200 для пошуку.
- **`<LocalTime>` і кеш головної зараз** — змінює D35 і 🧭 п. 14: пояс на клієнті підміняв би час на кожному завантаженні не з Києва, а `revalidateTag` не помітив би вихід запланованої новини (без події) — M2.12.

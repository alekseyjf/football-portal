# D24 — URL новини: `{slug}-{номер}`

- **Статус:** ✅ прийнято · 2026-10-08 · 👤 формат «slug + номер» + ⭐ деталі
- **Етап:** M1.4.1, M1.6
- **Замінює:** [P3-6](v5-content.md) (slug з суфіксом колізії), частину [D9](v5-foundation.md) («`slug` один на пост»)

## Контекст
Зараз URL — `/news/{slug}`, slug береться з EN-заголовка, мусить бути унікальним (при колізії — суфікс `-<hex>`) і однаковий для всіх мов. Змінити заголовок чи slug опублікованої новини, не зламавши посилань, неможливо; українська версія має англійський slug.

## Рішення
- 👤 URL — `/{locale}/news/{slug}-{number}`, де `number` — публічний номер поста (`Post.number`, послідовність Postgres, унікальний). Пост шукаємо **лише за номером**.
- ⭐ Свій slug для кожної мови (`PostTranslation.slug`): EN — з англійського заголовка, UK — транслітерація українського заголовка за офіційною таблицею (постанова КМУ № 55, 2010). Google радить локалізовані URL.
- ⭐ Невірний або застарілий slug → 308 на канонічний URL. Редирект зі старого slug працює автоматично (пошук за номером) — без таблиці старих slug-ів.
- ⭐ Slug фіксується при першій публікації; змінити — лише явно в адмінці (редирект спрацює).
- ⭐ Унікальність slug більше не потрібна — прибираємо суфікси колізій.

## Як роблять сильні команди
Числовий id + slug: ESPN (`/story/_/id/41234567/…`), The Athletic (`/5812345/…`), Stack Overflow (`/questions/12345/slug`, невірний slug → редирект на правильний).

## Наслідки
- Міграція: `Post.number` (backfill за `createdAt`), `PostTranslation.slug` (backfill з заголовків).
- Безпека: перебір номерів нічого не відкриває — чернетки й видалені за номером → 404.
- Web: розбір останнього `-<цифри>` у сегменті (slug теж може закінчуватись цифрами — беремо саме останню групу).
- Старі URL без номера → 404 (проду ще немає).

## Розглянуті альтернативи
- Короткий випадковий id (`…-k3j9x2`) — відхилено на користь номера 👤: номер коротший і читабельніший.
- Лише slug (як зараз) — відхилено: крихкий при зміні заголовка.

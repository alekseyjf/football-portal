# D24 — URL новини: `{slug}-{номер}`

- **Статус:** ✅ прийнято · 2026-10-08 · 👤 формат «slug + номер» · 🔁 2026-10-19 · 👤 один slug на всі мови (замість slug-а для кожної мови) · ✅ реалізовано в M1.4.1 · уточнено 2026-10-22 (M1.5.1): 👤 поле в адмінці, спільна транслітерація
- **Етап:** M1.4.1 (API, міграція, перехід web і admin), M1.5.1 ✅ (поле в адмінці), M1.6 (сторінка новини)
- **Замінює:** [P3-6](v5-content.md) (slug із суфіксом колізії, генерується один раз при створенні)
- **Уточнює:** [D9](v5-foundation.md) — `slug` і далі один на пост, але не унікальний

## Контекст
До M1.4.1 URL — `/{locale}/news/{slug}`: пост шукали за slug-ом з EN-заголовка, slug мусив бути унікальним (колізія → суфікс `-<6 hex>`, у постів з експорту Фази 0 — таймстемп `-1775515992287`) і генерувався один раз при створенні. Змінити slug опублікованої новини, не зламавши посилань, неможливо, а slug чернетки застрягав на робочому заголовку.

## Рішення
- 👤 URL — `/{locale}/news/{slug}-{number}`, де `number` — публічний номер новини (`Post.number`: послідовність Postgres, `@default(autoincrement())`, унікальний). Новину визначає **лише номер** — `GET /posts/{number}`.
- 👤 Slug **один на всі мови** — з EN-заголовка (EN обов'язкова, [D23](D23-content-languages.md)), лежить у `Post.slug`. Мову задає локаль на початку URL: `/en/news/arsenal-beat-chelsea-1042`, `/uk/news/arsenal-beat-chelsea-1042`.
- 👤 Унікальний лише номер: унікальність slug-а й суфікси колізій прибрано — дві новини з однаковим заголовком мають однаковий slug і різні номери.
- 👤 Slug пропонується автоматично з EN-заголовка, але редагується в адмінці (`slug` у `POST` / `PUT /posts`; лише `a-z`, `0-9` і одинарні дефіси, ≤ 80 символів):
  - поки `publishedAt` порожній — slug оновлюється разом з EN-заголовком;
  - щойно дата з'явилась (PUBLISHED або SCHEDULED) — slug зафіксовано; далі він змінюється лише явно з адмінки.
  - ⭐ Правило дивиться на стан **до** запиту: «опублікувати й змінити заголовок» одним запитом дає slug нового заголовка — *чому:* у новини, що виходить, slug збігається із заголовком, з яким її опубліковано. Заголовок без змін slug не чіпає — *чому:* інакше кожне збереження чернетки скидало б явно заданий slug.
  - 👤 (M1.5.1) Поле в адмінці містить лише те, що ввів редактор; slug з EN-заголовка — підказка (placeholder) і прев'ю адреси `/en/news/{slug}-{номер}` під полем; порожнє поле не надсилається — *чому:* явний slug фіксується з публікацією, тож у запит іде лише свідомо вписаний. Підказку будує та сама транслітерація, що й API: `slugify`, `slugifyTitle` і `SLUG_PATTERN` — у `packages/validation` (разом з тестами) — *чому:* дві копії розійшлися б, і підказка обіцяла б не ту адресу, яку збереже API.
- 👤 Старий чи невірний slug → **308** на канонічний URL: API віддає канонічний `slug`, сторінка web порівнює його з адресою й перенаправляє. Таблиця старих slug-ів не потрібна — новину знаходить номер.
- 👤 Номер в URL — лише цифри після **останнього** дефіса (slug теж може закінчуватись цифрами: `top-10-42`), у межах INTEGER. Інакше сторінка віддає 404, а не 500 (старі URL з таймстемпом: `…-1775675859414`). API на невалідний номер відповідає 400 — межа параметра ([backend Rule 12](../rules/backend.md)); web такий номер до API не надсилає.

## Як роблять сильні команди
Числовий id + slug: ESPN (`/story/_/id/41234567/…`), The Athletic (`/5812345/…`), Stack Overflow (`/questions/12345/slug`, невірний slug → редирект на правильний).

## Наслідки
- Міграція `0006_post_number` — SQL, який генерує Prisma: `Post.number` — `SERIAL` (номери наявним постам видає та сама послідовність), `Post_slug_key` прибрано; плюс у slug-ів з експорту Фази 0 знято суфікс-таймстемп (13 цифр). 👤 Без expand → backfill → contract: до релізу сумісність зі старим кодом не потрібна — старі процеси зупиняємо. Сід шукає пост з експорту за автором і `createdAt` — slug більше не унікальний.
- Новина, знята з публікації в DRAFT (`publishedAt` стирається), знову бере slug із заголовка — прийнятно: новину визначає номер, старий slug отримає 308.
- Безпека: перебір номерів нічого не відкриває — чернетки, заплановані й видалені за номером → 404. За пропусками в номерах видно приблизну кількість чернеток — як у Stack Overflow, прийнятно.
- Старі URL без номера → 404: проду й проіндексованих посилань ще немає, тож редиректи для них не потрібні.
- hreflang (M1.8): адреса іншої мови — той самий сегмент `{slug}-{number}` зі своєю локаллю.

## Розглянуті альтернативи
- Короткий випадковий id (`…-k3j9x2`) — відхилено на користь номера 👤: номер коротший і читабельніший.
- Лише slug (як було) — відхилено: крихкий при зміні заголовка, вимагає унікальності й суфіксів колізій.
- Свій slug для кожної мови (`PostTranslation.slug`, UK — транслітерація за постановою КМУ № 55 від 2010 р.) — ⭐ рекомендовано 2026-10-08, відхилено 2026-10-19 👤: мову вже задає локаль в URL, тож другий slug нової інформації не дає. Він коштував би колонку в перекладі, транслітерацію з винятками (апостроф, «зг», є / ї / й / ю / я на початку слова) і два slug-и, які треба окремо вести й фіксувати. Локалізовані слова в URL Google радить, але не вимагає: мовні версії він розрізняє за hreflang і локаллю в шляху.
- `Post.firstPublishedAt`, щоб slug лишався зафіксованим і після зняття новини в DRAFT, — відхилено 👤: зайва колонка заради рідкісного випадку; посилання й так веде номер (308).

# D44 — Обкладинка новини: опис для незрячих — мовою сторінки, підпис автора фото — на пості

- **Статус:** ✅ прийнято · 2026-10-20 · 👤 рішення власника (бриф M1.4.4) + ⭐ деталі (👤 погоджено після рев'ю) · ✅ реалізовано в M1.4.4
- **Етап:** M1.4.4 (API, міграція, мінімально адмінка й сайт), M1.5.1 ✅ (форма: прев'ю фото поруч з описом, нова адреса очищає опис і підпис), M1.6 (оформлення сторінки), M2.7 (власне сховище)
- **Уточнює:** [план](../football-plan.md), розділ 10 (`Post.coverImageAlt` → `PostTranslation.coverImageAlt`); [D23](D23-content-languages.md) — обов'язкове лише з публікації

## Контекст
Обкладинка — зовнішній https URL (`Post.coverImageUrl`, перевірка `IsMediaUrl`); власне сховище — M2.7. Сайт ставив фото alt = заголовок новини (екранний диктор читав його двічі — з фото і з h1), підпису автора фото не було ніде. План (розділ 10) пропонував обидва поля на пості: `Post.coverImageAlt`, `Post.coverImageCredit`.

## Рішення
- 👤 Опис для незрячих (`alt`) — **у перекладі**, `PostTranslation.coverImageAlt`: це текст для читача, тож він мовою сторінки, як заголовок. `/uk/…` показує український опис, а новина без українського перекладу — англійський разом з англійським текстом.
- 👤 Підпис автора фото — **на пості**, `Post.coverImageCredit`, один на всі мови. Вільний текст: агенція й / або фотограф («Stuart MacFarlane / Getty Images»). Слово «Фото:» / «Photo:» — з перекладів інтерфейсу сайту, у полі його немає.
- 👤 Обов'язкові — лише з публікації (PUBLISHED / SCHEDULED), як переклад UK у D23: опублікована чи запланована новина з обкладинкою має опис **у кожному своєму перекладі** й підпис; чернетка й архівна можуть бути неповними. Правило — чиста функція `resolvePostCoverImage` (`post-cover-image.ts`) з unit-тестами; вона дивиться на новину **після** запиту — наявні переклади разом з переданими. Коди помилок — `COVER_IMAGE_ALT_REQUIRED`, `COVER_IMAGE_CREDIT_REQUIRED`.
- 👤 Обкладинку прибрано (`coverImageUrl: null`) — опис у всіх перекладах і підпис очищаються: вони про конкретне фото, тож нове фото старого опису не успадкує. ⭐ Так само без обкладинки опис і підпис не зберігаються взагалі: передані відкидаються, а не дають 400 — *чому:* одне просте правило «немає фото — немає опису й підпису».
- ⭐ (рев'ю коду) Інша адреса — теж нове фото: наявні опис і підпис не переносяться, їх передають разом з адресою (опублікована без них → 400, у чернетці лишаються лише передані). Та сама адреса в запиті (форма надсилає всі поля) фото не змінює. Що записати в колонки — чиста функція `coverImageTextToStore`.
  - ⭐ (M1.5.1) Форма адмінки робить те саме: інша адреса фото (без урахування пробілів по краях) очищає опис кожною мовою й підпис — *чому:* форма надсилає всі поля, і без цього старий опис пішов би в API як опис нового фото. Поруч з описом — прев'ю фото звичайним `<img>`; не завантажилось — підказка перевірити адресу.
- ⭐ У `PUT` переклад передає title, excerpt і content повністю, а опис — лише якщо змінюється: не передано — лишається (поки фото те саме), `null` — прибрати — *чому:* клієнт, який про опис не знає, не зітре його.
- ⭐ (рев'ю коду) Опис потрібен лише в перекладах **увімкненими** мовами — *чому:* переклад вимкненою мовою сайт не показує, а задати йому опис не дає правило мов (P3-3: `UNSUPPORTED_LANGUAGE`); інакше така новина з обкладинкою не публікувалась би взагалі.
- 👤 Межі — у `packages/validation`, спільні для API й форми адмінки: опис — до 250 символів, підпис — до 100 (після trim; порожній рядок → 400).
- ⭐ Сайт: alt — з поля; без опису — порожній (`alt=""`), а не заголовок — *чому:* заголовок і так поруч (h1 новини, заголовок картки), дубль диктор прочитає двічі. Підпис — під фото на сторінці новини (`<figcaption>`); у картках стрічки підпису немає.
- 👤 Опис події на фото (caption: «Сака святкує гол на 88-й хвилині») — не зараз, [`ideas.md`](../ideas.md).

## Як роблять сильні команди
- Підпис фото — у кожному матеріалі: The Guardian — «Photograph: Stuart MacFarlane/Getty Images» під фото, BBC — «Image source, Getty Images»; на картках головної — без підпису.
- Опис для незрячих — локалізоване поле медіа (у Contentful опис asset-а перекладається для кожної мови), тож на сторінці він мовою читача.

## Наслідки
- Міграція `0007_post_cover_image_alt_credit` — дві nullable-колонки (SQL, який генерує Prisma) і дані: новинам з обкладинкою alt = заголовок перекладу (відтворювано). Підпис так не відновити — його вписує редакція. Сід з експортом Фази 0 робить те саме.
- 👤 Обкладинки тестових постів без прав на фото (pngtree.com, ukr.media — [`rules/content.md`](../rules/content.md)) міграція не чіпає: їх замінено легальними фото з Unsplash через API вже після неї (`PUT /posts/{id}` з адресою, описом EN / UK і підписом «Автор / Unsplash»); обкладинку отримав і третій пост. Локальний експорт Фази 0 (`content.json`) зберіг старі адреси — на порожній БД сід їх поверне.
- ⭐ `images.remotePatterns` у `next.config` не потрібні: сайт показує обкладинки через `next/image` з `unoptimized` — браузер вантажить фото прямо з `src`, оптимізатор Next (`/_next/image`, для якого й існують `remotePatterns`) не задіяний, тож сервер чужих адрес не фетчить. Знадобляться, якщо ввімкнемо оптимізацію (M2.7 / M2.12).
- Опублікована новина з обкладинкою без підпису (так лишаються наявні пости після міграції) не збережеться — 400 `COVER_IMAGE_CREDIT_REQUIRED`, доки підпис не задано. Свідомо: виправити дані один раз дешевше, ніж тримати виняток у правилі.
- (рев'ю коду) Мову (напр. `uk`) вимкнули → у новини змінили фото → мову ввімкнули знову: опис цією мовою зник разом зі старим фото, а задати новий, поки мова вимкнена, не можна (`UNSUPPORTED_LANGUAGE`). Тож у живої новини з обкладинкою немає опису цією мовою: сайт показує `alt=""`, а будь-який `PUT` → 400 `COVER_IMAGE_ALT_REQUIRED`, доки опис не передадуть (разом з перекладом цієї мови — у `PUT` він повний). Свідомо, як із підписом вище: вимкнути й знову ввімкнути мову — рідкісна дія адміна, а 400 одразу каже, чого бракує.
- Обмежень на рівні БД (CHECK) немає: опис — в іншій таблиці, CHECK його не бачить, а наявні пости без підпису не пройшли б перевірку. Правило тримає сервіс.
- Правило перевіряє стан, прочитаний до запису, без блокування рядка (як slug і публікація): два адміни, що одночасно змінюють одну новину, можуть розминутися з ним. Для редакції з 1–2 людей прийнятно; закриє оптимістичне блокування поста ([`backlog.md`](../backlog.md), тригер — другий редактор).
- M2.7 (`MediaAsset`): опис за мовами й підпис переїдуть до медіа-об'єкта разом з файлом, поля поста лишаться кешем (план, розділ 10).

## Розглянуті альтернативи
- `Post.coverImageAlt` (план, розділ 10) — відхилено: один опис на всі мови, тож на `/uk/…` alt був би англійською.
- «Фото: Getty Images» одним полем — відхилено: «Фото» / «Photo» — мова інтерфейсу, а в полі — лише автор фото.
- Обов'язкові й для чернетки — відхилено: чернетка може бути неповною, як переклад UK у D23.
- 400 на опис чи підпис без обкладинки — відхилено: див. «немає фото — немає опису й підпису».

# D49 — Спільний UI: `packages/ui` без збірки, вигляд тексту — `@tailwindcss/typography`

- **Статус:** ✅ прийнято · 2026-10-22 · 👤 рішення власника (бриф M1.5.1) + ⭐ деталі · ✅ реалізовано в M1.5.1
- **Етап:** M1.5.1 (пакет, рендерер, перегляд в адмінці), M1.6 (рендерер на сайті)
- **Уточнює:** [D25](D25-markdown-content.md) — де живе рендерер і як застосунки його збирають; frontend Rule 12 (спільний UI — у `packages/ui`)

## Контекст
Рендерер Markdown ([D25](D25-markdown-content.md)) — один для сайту й перегляду в адмінці, тож живе в спільному пакеті. Інший спільний пакет, `packages/validation`, збирається `tsc` у `dist`: його імпортує NestJS (CommonJS, Node), і turbo будує його перед `dev` / `build` / `typecheck` / `test`. Пакет UI — це компоненти React (TSX) і класи Tailwind, а Tailwind 4 не сканує файли поза застосунком сам.

## Рішення
- 👤 **Без збірки (Just-in-Time):** `exports` пакета — на `src/index.ts`; у `next.config.ts` web і admin — `transpilePackages: ['@football-portal/ui']`, Next компілює джерела сам. *Чому:* `validation` компілюється, бо її імпортує NestJS; UI споживають лише Next і Vitest — без `dist` швидший цикл розробки (гаряче оновлення без `tsc --watch`).
- 👤 **Класи Tailwind з пакета** — `@source "../../../../packages/ui/src"` у `globals.css` обох застосунків.
- 👤 **Вигляд тексту — `@tailwindcss/typography`** (`prose`), `@plugin` у `globals.css` обох застосунків. `prose` — вигляд, `components` react-markdown — поведінка (h1 → h2, `rel`, `<figure>` / `<figcaption>`). Ширина — у компоненті (`max-w-none`: міру рядка задає сторінка), окремих правил для адмінки немає. *Чому:* стандартна типографіка замість власного набору класів, які довелося б підтримувати.
- ⭐ Лапки довкола цитати `prose` не додає (`quotes: none`) — *чому:* за правилами редакції цитату пишуть у лапках самі ([`rules/content.md`](../rules/content.md)), інакше лапки подвоювались би, а закривна стояла б після підпису автора.
- ⭐ Пакет перевіряється сам: `typecheck` (свій `tsconfig`, `jsx: react-jsx`), `lint` — ті самі правила, що в застосунках (`eslint-config-next`), без правил саме Next (сторінок у пакеті немає, зображення тексту — звичайний `<img>`), `test` — Vitest + `renderToStaticMarkup` (без браузера). turbo підхоплює всі три.
- ⭐ Залежності — у пакеті (`react-markdown`, `remark-gfm`); `react` — peer (одна копія з застосунком), для тестів — devDependency тієї самої версії.

## Наслідки
- API пакет імпортувати не може (TSX-джерела без збірки) — і не має: UI потрібен лише web і admin.
- `tsc` застосунку перевіряє джерела пакета за своїм `tsconfig` (`strict`), Vitest застосунку імпортує пакет разом з його ESM-залежностями (react-markdown лише ESM) — перевірено в M1.5.1.
- Нова тема для `prose` на світлому сайті — у компоненті (`prose-invert` зараз, обидва застосунки темні).
- ⚠️ Turbopack dev кешує CSS на диску (`apps/*/.next/dev`): кеш, створений до появи `@source`, не підхоплює класи пакета — перегляд без стилів. Один раз видалити `.next/dev` застосунку; далі нові класи з `packages/ui` dev-сервер бачить одразу (перевірено в M1.5.1).
- `@source` і `@plugin` уже є й на сайті, хоч рендерер там з'явиться в M1.6: обгортка `prose` у тексті новини (`NewsPostView`) тепер має вигляд `prose`, текст — як був (класи на абзаці перекривають `prose`).

## Розглянуті альтернативи
- Збірка в `dist`, як `validation` — відхилено 👤: потребує `tsc --watch` у розробці, а споживачі (Next, Vitest) TypeScript компілюють і самі.
- Власні класи Tailwind у компонентах рендерера без нової залежності (⭐ на брифі) — відхилено 👤 на користь `prose`.

# D25 — Текст новин у Markdown

- **Статус:** ✅ прийнято · 2026-10-08 · 👤 формат + ⭐ правила рендеру
- **Етап:** M1.4.3, M1.5, M1.6

## Контекст
Зараз контент — простий текст (`whitespace-pre-wrap`). Власнику потрібні заголовки, списки, цитати, посилання, картинки, вбудовані відео й банер (4.4); обрано найпростіший у форматуванні варіант (4.3).

## Рішення
- 👤 `PostTranslation.content` зберігає Markdown; API віддає сирий текст, рендер — на web.
- ⭐ Рендер — `react-markdown` + `remark-gfm`, сирий HTML ігнорується; без `dangerouslySetInnerHTML`. Тож XSS через текст новини неможливий і DOMPurify не потрібен.
- ⭐ Дозволене: заголовки h2–h4 (h1 — заголовок новини), списки, цитати, посилання (`rel="noopener noreferrer"`, зовнішні — у новій вкладці), жирний / курсив, зображення (лише https), таблиці.
- ❓ YouTube-посилання окремим рядком → плеєр-фасад — вирішуємо на M1.6 (`open-questions.md`, OQ-2).
- ⭐ Один компонент рендеру для сайту й прев'ю в адмінці (`packages/ui`): що бачить редактор, те бачить читач.
- ⭐ Для `meta description` і майбутнього пошуку — текст без розмітки.

## Наслідки
- Колонка лишається `String` — міграція схеми не потрібна.
- ❓ Наявні пости: одинарні переноси рядків у Markdown зливаються в абзац → разова правка або `remark-breaks` (OQ-4).

## Розглянуті альтернативи
- HTML + візуальний редактор + DOMPurify — відхилено: складніше й ризиковіше (санітизація — постійне джерело вразливостей).
- Блоки JSON (Editor.js / Notion-подібні) — гнучко, але дорого для першої версії.

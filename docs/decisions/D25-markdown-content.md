# D25 — Текст новин у Markdown

- **Статус:** ✅ прийнято · 2026-10-08 · 👤 формат + ⭐ правила рендеру · уточнено 2026-10-19 (M1.4.3): 👤 що перевіряє API, де текст без розмітки, OQ-4
- **Етап:** M1.4.3 ✅ (контракт API, правила редакції), M1.5 (рендерер у `packages/ui`, прев'ю в адмінці), M1.6 (рендер на сайті)

## Контекст
Зараз контент — простий текст (`whitespace-pre-wrap`). Власнику потрібні заголовки, списки, цитати, посилання, картинки, вбудовані відео й банер (4.4); обрано найпростіший у форматуванні варіант (4.3).

## Рішення
- 👤 `PostTranslation.content` зберігає Markdown; API віддає сирий текст, рендер — на web.
- 👤 (2026-10-19) API Markdown не парсить і не перевіряє — лише довжину (`content` — 20…100 000 символів разом із розміткою, межа та сама). Правила безпеки — тільки в рендерері: одне місце, а не дві копії, що з часом розійдуться. Тож API збереже й `<script>`, і картинку з `http:` — рендерер їх відкине.
- ⭐ Markdown — лише `content`; `title` і `excerpt` — простий текст: заголовок — це h1 і `<title>`, анонс — стрічка й `meta description`. Так і в описі полів у Swagger.
- ⭐ Рендер — `react-markdown` + `remark-gfm`, сирий HTML ігнорується; без `dangerouslySetInnerHTML`. Тож XSS через текст новини неможливий і DOMPurify не потрібен.
- ⭐ Дозволене: заголовки h2–h4 (h1 — заголовок новини), списки, цитати, посилання (`rel="noopener noreferrer"`, зовнішні — у новій вкладці), жирний / курсив, зображення (лише https), таблиці.
- ❓ YouTube-посилання окремим рядком → плеєр-фасад — вирішуємо на M1.6 (`open-questions.md`, OQ-2).
- ⭐ Один компонент рендеру для сайту й прев'ю в адмінці (`packages/ui`): що бачить редактор, те бачить читач.
- ⭐ Для `meta description` і майбутнього пошуку — текст без розмітки. 👤 (2026-10-19) Його будує web — функція в `packages/ui` поруч із рендерером (M1.5 / M1.8); окремого поля у відповіді API немає.
- 👤 (2026-10-19) Стандартний Markdown, без `remark-breaks`: абзаци розділяє порожній рядок.

## Наслідки
- Колонка лишається `String` — міграція схеми не потрібна.
- ✅ OQ-4 закрито (M1.4.3): у 3 постах dev-БД і в експорті `prisma/seed-data/content.json` немає жодного переносу рядка — це тестові тексти в один рядок, і в Markdown вони виглядають так само, як зараз. Ні БД, ні експорт не змінювались.
- Поки рендерера немає (M1.5 / M1.6), сайт показує текст як є — розмітку (`## Заголовок`) видно буквально. Новин у Markdown ще немає, тож це нікому не заважає.
- Пошук у БД ([`ideas.md`](../ideas.md)) індексуватиме текст без розмітки на боці API / БД, а не web — де його будувати, вирішимо разом із пошуком.

## Розглянуті альтернативи
- HTML + візуальний редактор + DOMPurify — відхилено: складніше й ризиковіше (санітизація — постійне джерело вразливостей).
- Блоки JSON (Editor.js / Notion-подібні) — гнучко, але дорого для першої версії.

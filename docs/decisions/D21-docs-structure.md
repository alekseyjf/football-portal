# D21 — Документація: план розбито на частини в `docs/`

- **Статус:** ✅ прийнято · 2026-10-08 · 👤 рішення власника + ⭐ формат
- **Етап:** M1.1
- **Замінює:** єдиний файл `football-plan-new.md` (v4.7) → `docs/archive/football-plan-v4.7.md`

## Контекст
Старий план — один файл на ~1000 рядків: історія схеми v4, кілька шарів «актуалізацій», стан проєкту описано в чотирьох місцях (план, «Контекст для AI», `CLAUDE.md`, README), і вони вже розійшлися (109 чи 118 тестів). План почав збивати й повертати до гіршого стану проєкту.

## Рішення
- 👤 `docs/` — одне місце на кожен тип інформації:
  - `football-plan.md` — дорожня карта (віхи, етапи, чекбокси) + повний чекліст зробленого;
  - `decisions/` — реєстр рішень: D1–D20, P2-* … P5b-*, R5a-*, 🧭 — з тими самими ID (на них посилаються коментарі в коді), нові — окремими файлами з D21;
  - `rules/` — правила (архітектура, фронт, безпека, код, контент, процес);
  - `architecture.md` — як влаштовано систему;
  - `backlog.md`, `ideas.md`, `open-questions.md` — відкладене, ідеї, відкриті питання — окремо, щоб не засмічувати план;
  - `archive/` — історія (v1, v4.7, проміжний план v5) — щоб розуміти, від чого відмовились.
- 👤 Стан проєкту — лише в плані; README — опис і запуск; `CLAUDE.md` — контекст для AI (правила підключаються з `docs/rules/` через `@`-імпорт, коли власник їх перечитає).
- ⭐ Маркери в плані: 👤 рішення власника · ⭐ рекомендація з коротким «чому» · ❓ уточнити перед виконанням · ⚠️ розбіжність між очікуванням і кодом.
- ⭐ Нові рішення — у форматі ADR (Architecture Decision Record, Майкл Найгард): контекст → рішення → наслідки → альтернативи. Рішення не переписуються, а замінюються новими (поле «Статус» / «Замінює»). Так роблять GOV.UK, ThoughtWorks, Spotify.

## Наслідки
- План показує лише «що далі» і «що зроблено»; обґрунтування — у рішеннях; ідеї й відкладене не змішуються з роботою.
- AI оновлює план після кожного етапу ([D40](D40-development-process.md)).

## Розглянуті альтернативи
- Один файл — відхилено: саме він і застарів.
- Wiki / Notion — відхилено: документація має жити поруч із кодом і проходити PR разом зі змінами.
